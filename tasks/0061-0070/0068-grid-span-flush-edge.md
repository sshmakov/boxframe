# Суть проблемы

Правило 0066 (замкнутые интервалы с обеих сторон: `col_x[i] <= ix1 and
col_x[i+1] >= ix0`) не воспроизводит TO BE из `change-cells-span4.md`:
4×4 double-grid с кастомными `col_widths`/`row_heights` (перегородки на
абс. x=8,21,32 и y=2,5,8) и ребёнок-content 23×5 на rel (8,2), абс.
x[9,32) y[3,8) — его **правая** граница упирается в перегородку x=32,
**нижняя** — в y=8. TO BE требует, чтобы эти границы (и ячейки за ними:
колонка 4, ряд 4) остались нарисованными, а span охватывал только
колонки 2–3 × ряды 2–3 (абс. x[8,32) y[2,8)). Правило 0066 засчитывало
касание с обеих сторон — span расширялся на колонку 4 и ряд 4, и
границы x=32/y=8 гасились.

При этом TO BE (1)/(2) из `change-cells-span3.md` (задача 0066)
требуют, чтобы **левая/верхняя** граница, упирающаяся в границу
ячейки, засчитывалась (рамка ребёнка рисуется поверх неё). Т.е. касание
границы должно быть **асимметричным**.

Решение пользователя (2026-11-01): поведение span должно соответствовать
TO BE из `change-cells-span4.md` (и сохранять TO BE 1–3).

# Задача

Одна поправка к правилу 0066: касание границы асимметрично — half-open
прямоугольник ребёнка `[ix0, ix1)` против замкнутого диапазона ячейки
`[col_x[i], col_x[i+1]]`:

- колонки: `col_x[i] < ix1 and col_x[i+1] >= ix0` (было
  `col_x[i] <= ix1 and col_x[i+1] >= ix0`);
- ряды: `row_y[j] < iy1 and row_y[j+1] >= iy0` (было
  `row_y[j] <= iy1 and row_y[j+1] >= iy0`).

Левая/верхняя граница, упирающаяся в границу ячейки, засчитывается
(0066 сохранён); правая/нижняя — нет (рамка ребёнка на клетку короче
границы, которая остаётся нарисованной).

`crossed_v`/`crossed_h` (`rx0 <= p < rx1` / `ry0 <= q < ry1`, 0066) и
`covered()` (0065) — без изменений. Frame-узлы и junctions — по реально
отрисованным сегментам (0063, без изменений).

# Исследование

1. **Правило.** Для ребёнка с прямоугольником R (абс. half-open, кламп
   к внутренней области) — как в 0066: задеваемые колонки/ряды по
   `col_x`/`row_y`, span-область = bounding box этих ячеек. Изменение
   относительно 0066 — только правая/нижняя граница:
   - колонки: `col_x[i] < ix1` (было `col_x[i] <= ix1`);
   - ряды: `row_y[j] < iy1` (было `row_y[j] <= iy1`).
2. **Суперпозиция 0066.** 0068 ⊂ 0066: всё, что гасил 0068, гасил и
   0066 (half-open уже шире strict 0065). Плюс 0066 гасил ячейки за
   правой/нижней границей ребёнка, которая в 0068 остаётся нарисованной.
   Поведение без детей и с детьми, не упирающимися в правую/нижнюю
   границу, не меняется.
3. **TO BE 4 (`change-cells-span4.md`).** Ребёнок x[9,32) y[3,8):
   задевает колонки 2–3 (x=8 — касание левой границы: `col_x[1]=8 <
   ix1=23 and col_x[2]=21 >= ix0=8`; колонка 4 — `col_x[3]=32 < 23` —
   нет) и ряды 2–3 (y=2 — касание верхней границы; ряд 4 — `row_y[3]=8
   < iy1=8` — нет); `crossed_v={21}` (x=32: `9 <= 32 < 32` — нет),
   `crossed_h={5}` (y=8: `3 <= 8 < 8` — нет) → x=21 гасится по
   span-строкам, y=5 по span-колонкам, границы x=32/y=8 и колонка 4 /
   ряд 4 рисуются целиком. Воспроизводится побайтово.
4. **TO BE (1)/(2) (`change-cells-span3.md`).** Левая/верхняя граница
   упирается в границу ячейки — засчитывается (условие `col_x[i+1] >=
   ix0` / `row_y[j+1] >= iy0` не тронуто) → оба кейса без изменений,
   воспроизводятся побайтово.
5. **Влияние на существующие кейсы.** 6 кейсов размещения (span
   suppresses/vertical/2x2/fill/frame-nodes/uneven-split) + e2e — дети
   упираются в правую/нижнюю границу, span сжимается, ожидания
   пересчитаны. Кейсы TO BE 1/2/3 и 3×3 — дети не упираются в
   правую/нижнюю границу, без изменений.
6. **Parity.** Логика — целочисленные сравнения по тем же
   `col_x`/`row_y`/`v_parts`/`h_parts`, тривиально портируется (JS:
   те же объекты-множества); parity-тесты покрывают (новый кейс span с
   flush-границами на кастомном split + 2 flush-кейса на равномерном).
