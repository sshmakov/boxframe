# Суть проблемы

Span-подавление перегородок (задача 0062) убрало линии под
прямоугольниками детей, но frame-узлы на внешней рамке (`┬┴├┤`) и
внутренние junctions (`┼`) рисовались независимо от подавления — у
span-ячейки оставались «торчащие» концы линий (пример из
`change-cells-span.md`):

```
┌────────────┬───────────┬───────────┐     ← ┬ над span-ом «торчит»
│            │           │           │
│   lorem ipsum dolor    │           │
│   sit amet,            │           │
│   consectetur          │           │
├───adipiscing elit,   ──┼───────────┤     ← ┼ на краю span-а
│   sed do eiusmo        │           │
│            │           │           │
│            │           │           │
└────────────┴───────────┴───────────┘     ← ┴ под span-ом «торчит»
```

Пожелание пользователя (2026-10-31): удалить «торчащие» концы —
span-ячейка должна выглядеть целой:

```
┌────────────────────────┬───────────┐
│                        │           │
│   lorem ipsum dolor    │           │
│   sit amet,            │           │
│   consectetur          │           │
│   adipiscing elit,     ├───────────┤
│   sed do eiusmo        │           │
│                        │           │
│                        │           │
│                        │           │
└────────────────────────┴───────────┘
```

# Задача

Рисовать frame-узлы и junctions по **реально отрисованным** сегментам
перегородок вокруг них:

- frame-узел на внешней рамке (`┬`/`┴`/`├`/`┤`) деградирует до
  линейного символа рамки (`─`/`│`), если прилегающий сегмент
  перегородки подавлен span-ом;
- внутренний junction (`┼`) выбирается по 4 «рукам» (сегменты
  перегородки сверху/снизу/слева/справа): подавленная рука убирает
  соответствующее плечо (`┼ → ├/┤/┬/┴/│/─`), полный набор — `┼`;
  при частичном span-е возможны углы (`┌┐└┘`) и одиночные руки
  (линейный символ); ни одной руки — клетка не рисуется;
- junction под ребёнком (клетка покрыта) не рисуется (правило 0062);
- правило локальное (непосредственное прилегание): узел отражает
  сегмент, примыкающий к нему, а не «есть ли линия где-то дальше».

# Исследование

1. **Правило локального прилегания.** Узел в клетке P смотрит на 4
   соседние клетки: если сегмент перегородки в соседней клетке
   отрисован (не покрыт ребёнком) — рука есть. Для frame-узла «рука» —
   первая внутренняя клетка перегородки (frame-клетки вне внутренней
   области, дети их не покрывают).
2. **Таблица 16 комбинаций** (`_grid_junction()`/`gridJunction()`):
   `┼` (4 руки), `├┤┬┴` (3 руки), `┌┐└┘` (2 смежные), `│─` (2
   противоположные или 1 рука), `None/null` (0 рук — не рисовать).
   Все символы уже есть в стиле рамки (`BORDERS`), новых глифов нет.
3. **Порядок отрисовки сохранён.** Перегородки → frame-узлы →
   junctions: junction перезаписывает клетку перегородки на
   пересечении (как раньше), frame-узел перезаписывает клетку рамки.
4. **Углы возможны** при частичном span-е двумя и более детьми
   (ребёнок, закрывающий сегмент снизу, и ребёнок, закрывающий
   сегмент слева, но не саму клетку junction). Таблица это покрывает.
5. **Совместимость.** Вывод макетов с детьми в grid меняется:
   frame-узлы над span-ом становятся линейными. Это суть пожелания;
   макеты без детей не затрагиваются (все руки отрисованы).
6. **Parity.** Логика — таблица по 4 булевым, тривиально
   портируется; parity-тесты (9 span-кейсов) покрывают.
