# Суть проблемы

`grid` — «только имя» (аудит todo-0001, 2026-10-22): отрисовка идентична
`box` (общий путь `_draw_border()` + `_draw_content()`), дефолт 20×3 с
текстом `[grid]`, логики сетки нет — ни перегородок, ни ячеек. В бэклоге
(todo-0001, приоритет 1) висело решение: «реализовать рендер сетки
(параметры в `meta`) или убрать из палитры».

Требования шли из двух источников, и они совместимы:

1. **Аудит todo-0001** — рендер сетки: параметры в `meta` (замечание 4
   todo-0001: `meta` — устоявшееся место расширенных свойств).
2. **Дизайн-документ «Элементы boxframe.md»** (Obsidian) — `grid` как
   **сетка раскладки**, примитив тира 1 «любая 2D-раскладка»: каноничная
   фигура — сетка 3×2, параметры columns/rows.

Оба прочтения объединены в спецификации `todo-0005-grid-design.md`
(2026-10-30): **роль** (2D-сетка с перегородками) определяет отрисовку,
**параметры** (`meta.cols`/`meta.rows`) — структуру. Номера ячеек из
каноничной фигуры отклонены 2026-10-30 (решение пользователя) — сетка без
номеров. Авто-раскладка детей (grid-auto-flow) не поддерживается в чистом
виде (последовательное размещение не пропускает ячейки) — вынесено в
вариант 2 (snap к ячейке) как follow-up.

# Задача

Реализовать вариант 1 из `todo-0005-grid-design.md` (перегородки, без
номеров ячеек):

- внешняя рамка + внутренние перегородки по `meta.cols`/`meta.rows`
  (дефолт 3/2, некорректное значение → дефолт);
- эффективное число колонок/рядов клампится к внутренней области
  (каждая колонка/строка ≥ 1 клетки);
- структурный элемент: `content` и hint `[grid]` не рендерятся;
- fill — под перегородками; дети — поверх (контейнер, как `box`);
- `border_style=none` → без внешней рамки, перегородки solid;
- autosize отсутствует (размер — под контролем пользователя);
- дефолт нового блока — 24×8, content `''`;
- закрыть пункты todo-0001 по `grid` (приоритет 1) и «двойной клик»
  (`hline`/`vline`/`grid`).

# Исследование

1. **`grid` — общий путь в обоих рендерерах.** Веток для него нет ни в
   `_render_block()`, ни в `renderBlock()`: рамка + word-wrap + hint +
   fill. `grid` в `FILL_TYPES` (fill применяется). Новая ветка
   `_draw_grid()` вставляется рядом с `_draw_button()`/`_draw_divider()`.
2. **Бэкенд не меняется.** `LayoutService` не имеет типоспецифичной
   логики для `grid` (autosize нет — размер под контролем пользователя) →
   `LayoutService` и `store.js` не трогаются: все `normalize*` для grid
   early-return (прецеденты `text`/`button`/`divider`).
3. **Контейнер — однострочная правка UI.** Рендерер рисует детей у любого
   типа; ограничивает только `_findDropContainer()` (`editor.js`) —
   `box` → `box | grid`. Group-move использует тот же фильтр — работает
   бесплатно.
4. **HTML-оверлей не меняется.** `.block-inner` прозрачный, перегородки
   живут в ASCII-слое, внешняя рамка — общий путь `.block-border`.
   Парность покрывает ASCII.
5. **Узлы перегородок — из style map.** `BORDERS[style]` уже несёт
   `t_t` (┬), `b_b` (┴), `t_l` (├), `t_r` (┤), `b_b` (┼) + `h`/`v` —
   перегородки рисуются теми же символами, что и рамка (solid/dashed/
   dotted/double). `none` → внешней рамки нет, перегородки — solid
   (идентичность сетки — перегородки, а не рамка).
6. **Split детерминированный и тривиально портируется.**
   `x_i = (i·W) // eff_cols` — целочисленное деление, остаток
   распределяется вправо; `eff_cols = min(cols, W)` — вырожденные
   размеры не падают (каждая колонка/строка ≥ 1 клетки).
7. **Дети рисуются поверх перегородок.** Порядок в `_render_block`:
   рамка → fill → перегородки → дети. Внутренность ребёнка прозрачна —
   перегородка видна сквозь неё (проверено тестом: символ перегородки
   на месте, где нет контента ребёнка).
8. **`meta` — терпимый парсинг.** `grid_meta_int()` — прецедент
   `fill_char()`: не int (включая bool), < 1 → дефолт (3/2). Рендерер не
   падает на мусоре в `meta`.
9. **Совместимость.** Существующие `grid` в макетах изменят вывод: вместо
   текста `[grid]` — перегородки. Данные не теряются, миграция не
   делается (тип «только имя», осмысленного использования нет).
10. **Палитра не меняется (14)** — правка захардкоженного числа кнопок в
    e2e не нужна.
11. **E2e-инфраструктура.** В установленной версии Playwright нет
    `expect.poll` — для live-перерисовки (смена `cols` в панели → новый
    ASCII) нужен ручной поллинг (`_poll_until()` с
    `page.wait_for_timeout`).

# Выполнение задачи

## Python

- `services/renderer.py`:
  - `grid_meta_int(meta, key, default)` — положительный int из `meta`
    или дефолт (отклоняет bool, не-int, < 1);
  - `_draw_grid(block, style)` — clamp x/y/w/h; `framed = border_style
    != "none" and w >= 2 and h >= 2`; с рамкой — `_draw_border()` +
    внутренняя область `(x+1, y+1, w-2, h-2)`, без — весь блок; fill под
    перегородками; `eff_cols = min(cols, inner_w)`,
    `eff_rows = min(rows, inner_h)`; `part = style if framed else
    BORDERS["solid"]`; вертикальные перегородки (`part["v"]`, frame-узлы
    `t_t`/`b_l`), горизонтальные (`part["h"]`, frame-узлы `t_l`/`t_r`),
    внутренние пересечения — `part["b_b"]`;
  - ветка в `_render_block()`: `grid` → `_draw_grid()` +
    `_render_children_in_container()` (если есть дети); content/hint не
    рисуются.

# Замечания

1. **Grid — структурный элемент (прецедент линий).** Content и hint не
   рендерятся, двойной клик редактор не открывает. Если в будущем
   понадобится подпись сетки — это `meta`-опция, а не content.
2. **Autosize нет — осознанно.** Размер сетки под контролем пользователя
   (как у `box`); перегородки пересчитываются на каждом рендере (live
   re-layout при resize — «колонки/ряды растягиваются» из документа
   выполняется автоматически).
3. **Внутренность ребёнка прозрачна.** Перегородка видна сквозь пустые
   клетки ребёнка — это корректное поведение (ребёнок рисуется поверх,
   но не закрашивает сетку). Тесты фиксируют.
4. **Открытые вопросы todo-0005 (не блокируют):** gap (фаза 2 — каждая
   ячейка отдельной рамкой с зазором); snap к ячейке + span (вариант 2,
   follow-up, отдельная задача); мёртвый класс `block-grid` (вместе с
   пунктом «мёртвый код» todo-0001).
5. **E2e-поллинг.** `expect.poll` в установленной версии Playwright нет —
   хелпер `_poll_until()` (time.monotonic + wait_for_timeout) в
   `test_editor.py`; переиспользовать в будущих live-тестах.
6. **Кросс-ссылки:** todo-0001 (приоритет 1, пункты `grid` + «двойной
   клик» закрыты), todo-0005 (спецификация, вариант 1 реализован, вариант
   2 — follow-up), Obsidian `Aa/Элементы boxframe.md` (роль «сетка
   раскладки», тир 1), 0051 (механизм `meta`/word-wrap), 0057/0058
   (прецеденты дефолтов в `_blockDefaults`), 0059 (формат
   выводов-документа).
