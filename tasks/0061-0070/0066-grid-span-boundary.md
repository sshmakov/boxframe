# Суть проблемы

Правило «пересечения» из задачи 0065 (строгое `rx0 < p < rx1` +
half-open пересечение ячеек) не воспроизводит TO BE из
`change-cells-span3.md` в двух **граничных** сценариях — когда граница
прямоугольника ребёнка совпадает с перегородкой/границей ячейки:

- **TO BE (1):** левая граница ребёнка упирается в вертикальную
  перегородку x=13 (grid 38×11, 3×2, ребёнок-box 14×3 double на rel
  (12,0), абс. x[13,27) y[1,4)). Перегородка x=13 должна гаситься —
  рамка ребёнка рисуется поверх неё, — но 0065 (`rx0 < p`, т.е.
  `13 < 13`) её не засчитывал. TO BE (1) также показывает, что span
  должен охватить все 3 колонки (правая граница ребёнка x=26 заходит за
  границу x=25).
- **TO BE (2):** верхняя граница ребёнка упирается в горизонтальную
  перегородку y=5 (тот же grid, ребёнок-box 14×3 double на rel (12,4),
  абс. x[13,27) y[5,8)). Span должен распространиться на ряд выше
  (ребёнок задевает нижнюю границу ряда 1) и перегородка y=5 должна
  гаситься, но 0065 (half-open: ряд задевается, только если
  `row_y[j] < iy1`, т.е. `4 < 3` — нет) ряд выше не задевал, и y=5 не
  гасилась.

Решение пользователя (2026-10-31): поведение span должно соответствовать
TO BE (1) и TO BE (2) из `change-cells-span3.md`.

# Задача

Две поправки к правилу 0065:

1. **Замкнутое пересечение ячеек.** Ячейка задевается, если
   `col_x[i] <= ix1 and col_x[i+1] >= ix0` (аналогично для рядов по
   `row_y`) — касание границы засчитывается: ребёнок, упирающийся в
   границу ячейки, занимает и ячейку по другую сторону.
2. **Пересечение перегородки с включением границы.** `crossed_v`/
   `crossed_h` — `rx0 <= p < rx1` / `ry0 <= q < ry1` (левая/верхняя
   граница включена, правая/нижняя — нет): перегородка под самой
   левой/верхней границей ребёнка считается пересечённой (рамка
   ребёнка рисуется поверх неё).

`covered()` (логика 0065) — без изменений. Frame-узлы и junctions — по
реально отрисованным сегментам (0063, без изменений).

# Исследование

1. **Правило.** Для ребёнка с прямоугольником R (абс. half-open,
   кламп к внутренней области) — как в 0065: задеваемые колонки/ряды
   по `col_x`/`row_y`, span-область = bounding box этих ячеек. Изменения
   относительно 0065:
   - колонки: `col_x[i] <= ix1 and col_x[i+1] >= ix0` (было
     `col_x[i] < ix1 and col_x[i+1] > ix0`);
   - ряды: `row_y[j] <= iy1 and row_y[j+1] >= iy0` (было
     `row_y[j] < iy1 and row_y[j+1] > iy0`);
   - `crossed_v = {p ∈ v_parts : rx0 <= p < rx1}` (было
     `rx0 < p < rx1`);
   - `crossed_h = {q ∈ h_parts : ry0 <= q < ry1}` (было
     `ry0 < q < ry1`).
2. **Суперпозиция 0065.** 0066 ⊇ 0065: всё, что гасил 0065, гасится и
   сейчас (замкнутый интервал шире, включение границы шире). Плюс
   гасятся перегородки/ячейки, которые ребёнок лишь касается
   (граничные случаи). Поведение без детей и с детьми, не упирающимися
   в границы, не меняется.
3. **TO BE (1) (`change-cells-span3.md`).** Ребёнок x[13,27) y[1,4):
   задевает все 3 колонки (x=13 и x=25 — касание/пересечение), ряд 1
   (y[1,5)); `crossed_v={13,25}`, `crossed_h={}` (y=5: `1 <= 5 < 4` —
   нет) → x=13 и x=25 гасятся по ряду 1, y=5 рисуется целиком, junctions
   (13,5)/(25,5) → ┬ (верхняя рука гасится). Воспроизводится побайтово.
4. **TO BE (2) (`change-cells-span3.md`).** Ребёнок x[13,27) y[5,8):
   задевает все 3 колонки и **оба** ряда (y=5 — касание нижней границы
   ряда 1: `row_y[1]=4 <= iy1=7 and row_y[0]... ` ряд 1 задевается по
   замкнутому правилу); `crossed_v={13,25}`, `crossed_h={5}` (y=5:
   `5 <= 5 < 8` — да) → все перегородки гасятся, остаётся только внешняя
   рамка. Воспроизводится побайтово.
5. **Влияние на существующие кейсы.** 5 кейсов размещения (span
   suppresses/vertical/2x2/fill/frame-nodes) + `children_render_over_
   partitions` + e2e — дети упираются в границы, span расширяется,
   ожидания пересчитаны. Кейсы TO BE 1/2 (`change-cells-span.md`/
   `change-cells-span2.md`) и 3×3 — дети не упираются в границы, без
   изменений.
6. **Parity.** Логика — целочисленные сравнения по тем же
   `col_x`/`row_y`/`v_parts`/`h_parts`, тривиально портируется (JS:
   те же объекты-множества); parity-тесты покрывают.
