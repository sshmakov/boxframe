# Суть проблемы

Правило «целых ячеек» из задачи 0064 (внутри span-области —
объединения целых ячеек, которые пересекает ребёнок — не рисуются ВСЕ
перегородки) не воспроизводит TO BE из `change-cells-span2.md`.
Проверка (2026-10-31): в сценарии TO BE (grid 38×11, 3×2, ребёнок-box
18×3 с рамкой double на (16,5), пересекает ячейки 2–3 нижнего ряда и
перешагивает только вертикальную перегородку x=25) правило 0064
гасило бы горизонтальную перегородку y=5 на всём протяжении span-области
x[13,37) и вертикальную x=13 по span-строкам y[5,10) — хотя ребёнок ни
одну из них не пересекает. TO BE нарисован по правилу **«пересечения»**:
гасится только та перегородка, которую ребёнок реально перешагивает.

Решение пользователя (2026-10-31): переключиться на правило
«пересечения».

# Задача

Внутри span-области ребёнка (объединение целых ячеек, 0064)
перегородка подавляется **только там, где её пересекает прямоугольник
ребёнка**:

- вертикальная перегородка — по span-строкам, только если ребёнок её
  перешагивает (`rx0 < p < rx1`);
- горизонтальная — по span-колонкам, только если перешагивает
  (`ry0 < q < ry1`);
- клетка на пересечении вертикальной и горизонтальной — только если
  ребёнок перешагивает **обе**.

Итог: span-ячейка сохраняет границы тех ячеек, которые ребёнок не
пересекает. Frame-узлы и junctions — по реально отрисованным сегментам
(0063, без изменений).

# Исследование

1. **Правило.** Для ребёнка с прямоугольником R (абс. half-open,
   кламп к внутренней области) — как в 0064: пересекаемые колонки/ряды
   по `col_x`/`row_y`, span-область = bounding box этих ячеек. Плюс
   множества пересечённых перегородок: `crossed_v = {p ∈ v_parts :
   rx0 < p < rx1}`, `crossed_h = {q ∈ h_parts : ry0 < q < ry1}`.
   Клетка (px, py) в span-области покрыта, если:
   - px — вертикальная перегородка из `crossed_v`, и (py не на
     горизонтальной перегородке или она в `crossed_h`); ИЛИ
   - py — горизонтальная перегородка из `crossed_h`, и (px не на
     вертикальной перегородке или она в `crossed_v`).
2. **Суперпозиция 0064.** 0065 ⊂ 0064: всё, что гасил 0064, гасится и
   сейчас, только уже не всё, что гасил 0064. Поведение без детей и с
   детьми, пересекающими все перегородки span-области (например,
   заполняющими её целиком), не меняется.
3. **Совместимость.** Вывод макетов с детьми, пересекающими не все
   перегородки span-области, меняется: непересечённые перегородки
   внутри span-области снова рисуются. Это суть TO BE 2.
4. **TO BE 1 (`change-cells-span.md`).** Ребёнок 19×5 пересекает и x=13,
   и y=5 — обе в `crossed_v`/`crossed_h` → вывод не меняется, кейс
   проходит без правок.
5. **TO BE 2 (`change-cells-span2.md`).** Ребёнок 18×3 пересекает только
   x=25: `crossed_v={25}`, `crossed_h={}` → y=5 рисуется целиком, x=13
   рисуется целиком, x=25 гасится по span-строкам y[5,10); junction
   (25,5) → ┴, frame-узлы (25,10) → ─, (13,10) → ┴. Воспроизводится
   побайтово.
6. **Parity.** Логика — целочисленные сравнения по тем же
   `col_x`/`row_y`/`v_parts`/`h_parts`, тривиально портируется (JS:
   объекты-множества `vParts`/`hParts`/`crossedV`/`crossedH`);
   parity-тесты покрывают.
7. **E2E.** В сценарии e2e-теста (box 13×3 в ячейках 1–2 верхнего ряда
   grid 24×8) ребёнок пересекает только вертикальную перегородку —
   горизонтальных в span-области нет → вывод не меняется.
