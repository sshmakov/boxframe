# Суть проблемы

Редактор имел четыре взаимно связанных недостатка:

1. **Рамка границ макета** — пунктирный div `layout-bounds` рисовался
   поверх канваса в размере логического макета (80×24 по умолчанию).
   Размер макета — метаданные (есть в API/экспорте), а рамка создавала
   визуальное ощущение «ограниченного поля» и шумела на канвасе.
2. **Канвас не занимал всё свободное пространство** — тёмная область
   (`#1a1a2e`) была размером только с отрисованный макет, остальная
   часть контента — фон страницы. Редактор не выглядел полноэкранным
   рабочим пространством.
3. **Блоки нельзя было перетащить за правую/нижнюю границу** —
   `mousemove` был привязан к контейнеру канваса: как только курсор
   выходил за его пределы, drag обрывался. Автоскролла не было, а
   `_pixelToGrid()` не учитывал смещение скролла (рабочая зона
   скролла была разбита между `.editor-content` и `.canvas-container`).
4. **Пустые строки в конце экспорта** — сетка рендерилась на всю
   высоту макета, поэтому ASCII/Markdown/Copy содержали хвост пустых
   строк (например, 21 пустая строка у макета 80×24 с одним блоком
   10×3). Для AI-readable формата это шум: длина текста не несёт
   информации, высота макета и так в метаданных.

# Задача

- Убрать отображение границ макета в редакторе.
- Отображать редактор (канвас) на всё свободное пространство.
- Позволять перемещать элементы за границы экрана вправо и вниз.
- При экспорте удалять пустые строки в конце текста.

# Исследование

1. **Рамка рисовалась в двух местах** — API `/api/layouts/{id}/render`
   (`bounds_html`) и JS `renderHtml()` (static-режим) + стиль
   `.layout-bounds` в `editor.css`. Удаление требует правки обоих
   рендереров, CSS и двух тестовых файлов (API и JS), где наличие
   рамки было зафиксировано как фича (задача 0019).
2. **Раскладка канваса** — `.editor-content` (grid-элемент) →
   `.canvas-container`. До изменения: контейнер был размером с
   контент, вертикальный скролл жил в `.editor-content`,
   горизонтальный — в контейнере. `_pixelToGrid()` не учитывал
   скролл вообще — корректно работал только пока канвас помещался
   на экране. После изменения контейнер занимает 100%×100% родителя
   (у grid-элемента высота определена растяжкой) и является
   единственным скроллером — маппинг предсказуем.
3. **Drag обрывался на границе контейнера** — `@mousemove` был на
   `.canvas-container`. `mouseup` уже был глобальным
   (`_bindGlobalMouseUp`) — решение симметричное: глобальный
   `mousemove` на `document`, контейнерная привязка удалена из обоих
   HTML (web + static).
4. **Скролл-офсет** — `_pixelToGrid()` дополнен
   `container.scrollLeft/scrollTop`: координаты корректны при
   прокрученном канвасе и когда курсор за его пределами.
5. **Автоскролл** — 40px-зона у каждого края, шаг ≤ 16px на
   событие `mousemove`. Осознанное упрощение: скролл идёт только
   пока движется мышь (нет rAF-цикла при неподвижном курсоре).
6. **Хвостовые пустые строки** — отбрасываются в `render()` обоих
   рендереров (parity сохраняется: правило идентично). Формат
   становится чище сам по себе: затронуты экспорт, Copy и канвас
   редактора (визуально не меняется — у слоя `.ascii-art` жёсткая
   высота). Пустой макет теперь рендерится как пустая строка;
   `export_markdown()` изменён с `if not ascii_art` на
   `if ascii_art is None`, чтобы пустой макет экспортировался, а не
   давал `null`.
7. **Гонка в e2e** — редактор при старте рендерит канвас дважды
   (сразу и после измерения реального размера шрифта,
   `init()` → `refreshRender()` → `$nextTick` → `refreshRender()`).
   `bounding_box()` мог поймать detached-элемент между
   перерисовками — тест оказался фликующим (1 из 5 запусков).
   Решение: атомарный снимок обоих боксов (wrapper + block) в одном
   `page.evaluate()` — они гарантированно из одного поколения DOM.

# Замечания

1. **Оригин (0,0) — жёсткое ограничение** — блоки нельзя разместить
   левее/выше канваса (запрос был только про вправо/вниз). Если
   понадобится «бесконечная» сетка в обе стороны — нужно менять
   координатную модель (отрицательные x/y), а не только drag.
2. **Автоскролл без rAF** — при неподвижном курсоре у края скролл
   останавливается. Если это будет мешать, добавить цикл
   `requestAnimationFrame` на время drag.
3. **Размер макета — чистые метаданные** — рамка не отображается,
   длина экспорта от высоты макета не зависит. Логический размер
   виден только в API/JSON-экспорте.
4. **e2e-гонка с двойным рендером** — атомарный снимок боксов —
   обходной путь. Если рендер при старте переработать (один рендер
   после измерения шрифта), тест можно упростить до
   `bounding_box()` без поллинга.
5. **Рамка `layout-bounds` удалена из обоих режимов** (web + static).
   Если понадобится вернуть — реализация в git-истории (задача 0019),
   вопрос только в том, показывать ли её по умолчанию.
