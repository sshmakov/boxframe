# Суть проблемы

Прилипание (`header`/`footer`/`sidebar` в `box`, 0074/0075/0077)
решено **в render-time**: условие по сохранённым относительным
координатам (`y < 0`, `y + h > inner_h`, `x < 0` / `x + w > inner_w`),
эффективная геометрия пересчитывается каждый рендер (`_plan_attached` /
`planAttached`). Запросы к данным при этом не изменяются — при
правильных сохранённых координатах приклеенный блок автоматически
следует за любыми новыми размерами `box`.

Но **редактор умеет портить сохранённые координаты при ресайзе `box`**,
из-за чего прилипание теряется:

1. **Дрег верхней/левой грани `box` (главный баг).**
   `_commitBlockResize` (`editor.js`) при движении `nw`/`ne`/`sw` углов
   пересчитывает координаты **всех детей** через `_absToRel` с одной и
   той же дельтой. Для `header` с сохранённым `y = −1` дрег верхней
   грани **вниз** на N даёт сохранённый `y = N − 1`; при **N ≥ 2**
   условие `y < 0` нарушается — `header` **отклеивается**. Зеркально:
   `sidebar` с `x = −1` при дегре левой грани вправо на N ≥ 2
   (`x = N − 1`) отклеивается.
2. **Зеркальный случай — `footer` / right-`sidebar` с «внутренним»
   сохранённым значением** (например `footer` прижат точно: `y + h =
   inner_h` — не приклеен, а прилип из-за последующего сжатия снизу;
   сохранённое `y` тогда велико). При **росте** `box` сверху/слева
   (дельта детей отрицательная) условие `y + h > inner_h` может
   перестать выполняться — отклейка.
3. **Group-ресайз `box` + приклеенного ребёнка.** Если выделены `box`
   и его приклеенный `header` и тянется ручка selection-frame
   (`resizeGroup`), каждому применяется одинаковая дельта к
   сохранённым координатам — `header` уезжает внутрь и отклеивается.
   (Отдельный баг того же кода: group-ресайз применяет дельту дельта к
   сохранённым **относительным** координатам детей, тогда как для детей
   смещение абсолютной позиции родителя даёт **удвоенный** сдвиг —
   см. исследование п.4.)
4. **Ресайз самого приклеенного блока.** Ручка стоит на эффективном
   rect; коммит пишет в данные эффективную внутреннюю ширину `box` в
   `width` (для `header`/`footer`) и `x`/`y` при дреге грани. Пока
   блок приклеен — безвредно (параллельное измерение игнорируется), но
   **после отклейки блок «раздут»** до внутренней ширины `box` и
   сидит не там, где был.

Что **уже** работает корректно (проверено по коду, нужно закрепить
тестами):

- ресайз `box` за **правый/нижний** край и смена `width`/`height` в
  панели свойств — начало координат `box` не движется, сохранённые
  координаты детей не меняются, эффективная геометрия прилипания
  сама следует за новыми размерами;
- **перемещение** `box` целиком — дети-дети не обновляются
  (`_commitGroupMove`: «parent moves with the group… no update»),
  смещения сохраняются;
- **уменьшение** `box` сверху/слева — отсечение усиливается
  (`y` становится ещё меньше), прилипание не теряется.

# Задача

Гарантировать, что при **любом** ресайзе `box` (любой угол, панель
свойств, group-ресайз) приклеенные `header`/`footer`/`sidebar`
остаются приклеенными; устранить порчу сохранённых координат при
ресайзе самих приклеенных блоков; зафиксировать поведение при
вырожденных размерах `box`. Бэкенд и правила рендера прилипания не
меняются.

# Варианты

## Вариант A — якорь при коммите ресайза в редакторе (рекомендация)

Данные остаются «сырыми» (как сейчас); при **коммите ресайза `box`**
редактор для каждого приклеенного ребёнка сохраняет **якорное
смещение от подвижной грани** вместо геометрического пересчёта через
`_absToRel` (кламп так, чтобы условие прилипания осталось выполненным).

- Плюсы: минимальный точечный фикс в одном месте
  (`_commitBlockResize`); ничего не ломает в существующем
  геометрическом механизме 0074/0075/0077; отклейка перетаскиванием
  остаётся возможной (коммит дрега самого блока свободный).
- Минусы: «магия» распределена по точкам коммита (нельзя пропустить
  новую точку ресайза в будущем); корректность прилипания после
  произвольных операций зависит от дисциплины редактора.

## Вариант B — нормализация сохранённых координат приклеенного chrome

Инвариант в сторе/редакторе: пока дочерний `header`/`footer`/`sidebar`
в `box` **приклеен**, его координата вдоль оси прилипания
**принудительно** поддерживается (`y = −1`, `y = inner_h − h`,
`x = −1`, `x = inner_w − w`) при любой мутации `box`.

- Плюсы: инвариант сильнее — координаты всегда «канонические»,
  сторонние клиенты (API-клиенты, импорт) получают предсказуемые
  данные.
- Минусы: ломает **намеренную** отклейку перетаскиванием (геометрия —
  единственный способ отклеить); конфликты при импорте/undo; writes
  при каждом ресайзе (undo-записи); расходится с уже принятой
  философией «render-time вывод, данные не трогаем» (0074/0075/0077,
  перегородки `grid` 0061). Отклонён как основной.

## Вариант C — явный флаг `meta.attached`

Прилипание оптимизируется/фиксируется флагом, ставится при drop.

- Минусы: флаг «протухает» при drag (уже отклонено для `header` в
  todo-0007, для `sidebar` в todo-0009 п.2/вариант 2); дублирует
  геометрию. Отклонён.

## Сравнение

| | A — якорь при коммите | B — нормализация в сторе | C — флаг |
|---|---|---|---|
| Объём изменений | редактор, 2–3 функции | стор + редактор + импорт | редактор + рендерер |
| Намеренная отклейка drag'ом | сохраняется | ломается | требует снятия флага |
| Согласованность с 0074/0075/0077 | да | частично | нет |
| Гарантии сторонним клиентам | слабые (только редактор) | сильные | средние |
| Рекомендация | **да** | нет | нет |

# Ключевые решения (согласованы 2026-11-10)

1. **Механизм — вариант A.** Якорь сохраняется только в точках
   ресайза `box`; дрег самого приклеенного блока остаётся свободным
   (отклейка перетаскиванием — штатный UX, см. п.8).
2. **Якорь при дреге граней `box`.** Для приклеенного ребёнка
   пересчёт координат **не** через `_absToRel` общим дельтой, а с
   клампом, сохраняющим прилипание:
   - `header`: сохранённый `y' = min(y + N, −1)`
     (N — сдвиг верхней грани вниз; `y ≤ −2` сохраняется как щель,
     `y = −1` не даёт отклеиться ни при каком N);
   - `footer`: `y' = max(y + N, inner_h' − h + 1)`
     (inner_h' — новая внутренняя высота);
   - left-`sidebar`: `x' = min(x + N, −1)`;
   - right-`sidebar`: `x' = max(x + N, inner_w' − w + 1)`.
   Измерение **вдоль** грани (`x` для header/footer, `y` для sidebar)
   при дреге перпендикулярной грани `box` не меняется (как сейчас).
   Следствие (квантование): у header со `y = −5` (большая щель над
   шапкой) после сильного сдвига грани вниз щель схлопнется до
   касания — **решено (2026-11-10): прилипание важнее точной
   сохранности щели**.
3. **Сдвиг фиксированной грани не двигает chrome.** При дреге
   `se`/`sw`/`ne` нижняя/верхняя фиксированная грань `box` не
   меняется, и приклеенные `footer`/`header` не должны сдвигаться
   вдоль своей оси (их эффективный rect anchored к этой грани;
   сохранённая координата подгоняется формулами п.2).
4. **Минимум `box` с приклеенными детьми — 4×4** (внутренняя область
   ≥ 2×2): кламп в превью-дреге и на коммите. **Решено (2026-11-10):
   только для `box` с приклеенными детьми**, остальные `box` клампятся
   к общему минимуму 2×2 (свобода мелких рамок сохранена). Без клампа
   при `inner_w < 1 or inner_h < 1` `_plan_attached` делает
   early-return и **все** прилипание молча теряется, дети рендерятся
   обычными box (альтернатива — глобальный кламп всех `box` —
   отклонена, см. follow-up 3).
5. **Group-ресайз `box` + его приклеенного ребёнка:** приклеенные дети
   исключаются из трансформации (follow за `box` автоматический);
   для остальных детей дельта применяется в **абсолютных** координатах
   (пересчёт туда/обратно), что попутно чинит удвоенный сдвиг
   (исследование п.4).
6. **Ресайз самого приклеенного блока:** дрег меняет только
   перпендикулярное измерение — `header`/`footer` только `height`,
   `sidebar` только `width`; `x`/`y` (и параллельное измерение) в
   данные не пишутся. При отклейке блок сохраняет честные
   сохранённые размеры, а не раздутую внутреннюю ширину `box`.
7. **Верхняя/левая грань `box` не может «съесть» приклеенный chrome
   целиком:** эстетика, не инвариант — при сильном сжатии эффективные
   полосы `header`/`footer` перекрываются; правила доминанты/составного
   усечения (0077/0078) и кламп `max(1, h)` уже определяют вывод.
   Зафиксировать деградацию тестами (пример ниже), без новых правил.
8. **Отклейка остаётся геометрической:** единственный способ отклеить
   — перетащить приклеенный блок от края (коммит дрега самого блока
   свободный, п.1). Ресайз `box` отклеить не может.

# Правила (редактор)

Обозначения как в 0074/0077: `box` — абсолютные `(px, py)`,
`(pw, ph)`, `inner_w = pw − 2`, `inner_h = ph − 2`; ребёнок —
относительные `(cx, cy)`, `(cw, ch)`.

Пусть ресайз `box` сдвигает верхнюю грань на `N` вниз
(`py' = py + N`), левую на `M` вправо (`px' = px + M`); новые
`inner_w'`, `inner_h'`. Коммит ресайза `box` для детей:

| ребёнок | было приклеено | стало сохранённым | прилипание |
|---|---|---|---|
| `header` | `cy < 0` | `cy' = min(cy + N, −1)` | ✓ всегда |
| `footer` | `cy + ch > inner_h` | `cy' = max(cy + N, inner_h' − ch + 1)` | ✓ всегда |
| `sidebar` left | `cx < 0` | `cx' = min(cx + M, −1)` | ✓ всегда |
| `sidebar` right | `cx + cw > inner_w` | `cx' = max(cx + M, inner_w' − cw + 1)` | ✓ всегда |
| ordinary child | — | через `_absToRel` (как сейчас) | — |

- дрег `se`/`ne`/`sw`/`nw`: применяются только те из `N`/`M`, чьи
  грани двигаются (для `se` — `N = M = 0`, дети не трогаются вовсе);
- приклеенный ребёнок, выделенный вместе с `box` (group), из общей
  трансформации исключается (решение 5);
- коммит ресайза приклеенного блока пишет только `height`
  (`header`/`footer`) или `width` (`sidebar`), минимум — 1 (решение 6);
- кламп размера `box` с приклеенными детьми: `w,h ≥ 4` (решение 4).

Деградация при сильном сжатии (всё ещё «приклеено», вид вырожденный —
зафиксировать тестами, без новых правил рендера):

```
box с header h=3 + footer h=3, сжат до 5 внутренней высоты:
┌──────────┐
│ header   │      линии header (row inner_h−ch) и footer (row 0)
├──────────┤      пересекаются; контентные области схлопнуты;
│ footer   │      junctions ├/┤ по действующим правилам
└──────────┘
```

# Исследование (факты из кода, 2026-11-10)

1. `_plan_attached` (`services/renderer.py`) / `planAttached`
   (`static/js/core/renderer.js`): условие и эффективная геометрия —
   чистый render-time вывод; при корректных сохранённых координатах
   прилипание устойчиво к любым размерам `box` (кроме `inner_w < 1`
   or `inner_h < 1` → early-return, все `attached = False`).
2. `_commitBlockResize` (`editor.js`): при `nw`/`sw` — `absX`
   меняется, координаты детей пересчитываются `_absToRel` с общим
   дельтой → дрейф сохранённых `x`/`y` (проблема 1/2). Для `se` —
   `x`/`y` не меняются → прилипание сохраняется.
3. `_commitGroupMove`: ребёнок с родителем в группе не обновляется
   вовсе → смещение сохраняется (перемещение `box` безопасно).
4. Group-ресайз (`resizeGroup` в `_commitBlockResize`): дельта
   применяется к сохранённым (`o.x`, `o.y`) координатам; для детей
   сохранённые координаты относительные, а дельта выведена из
   абсолютных rect → при ресайзе группы с родителем в группе ребёнок
   сдвигается **дважды** (скрытый баг, чинить в этой задаче).
5. Панель свойств (`applyPropValue`): меняет только `width`/`height`,
   `x`/`y` не трогает → детей не сдвигает → прилипание сохраняется.
6. Минимумы превью-дрога ресайза: `minW/minH = 2` для `box`
   (строки ~1538) → `box` 2×2 возможен, внутренняя область пустая →
   early-return в `_plan_attached`.
7. Ручка ресайза приклеенного блока позиционируется по эффективному
   rect (`_absoluteRect`), коммит пишет эффективную геометрию в
   данные (проблема 4).
8. Бэкенд (`LayoutService`, API): типоспецифичной логики нет,
   изменений не требует.
