# Суть проблемы

Из 14 типов блоков в `BLOCK_TYPES` реально работают по назначению 5:
`box`, `text`, `hline`, `vline`, `button`. Остальные — либо семантические
имена без характерной отрисовки, либо не доделаны:

- `divider` дублирует роль `hline`, но рендерится как обычный блок с полной
  рамкой (пробел зафиксирован в задаче 0014, не закрыт);
- `grid` не имеет никакой логики сетки — рендерится как обычный `box`;
- `input`, `textarea`, `image` не имеют характерной отрисовки
  (подчёркивание/курсор, плейсхолдер изображения); `image` получил только
  поддержку `meta.fill` (0051);
- `header`, `footer`, `sidebar`, `content` — только имена: отрисовка
  идентична `box`, семантических дефолтов (полная ширина, позиция,
  пропорции) нет.

Сквозные пробелы, оставшиеся после аудита 2026-09-06: API не валидирует
`block_type`/`border_style`, двойной клик открывает редактор контента для
линий (контент линии не рендерится), есть мёртвый код. Пробелы
«вложенность в UI» и «`meta` не используется» закрыты задачами 0035–0039
и 0051–0054.

# Задача

Привести набор компонентов к согласованному состоянию: каждый тип в палитре
либо рендерится характерным для себя образом, либо убирается из
`BLOCK_TYPES`. Закрыть оставшиеся сквозные пробелы (валидация,
двойной клик, мёртвый код).

Ключевые факты (2026-10-22):

1. Особые пути отрисовки — `_draw_line()` (hline/vline, со стрелками),
   `_draw_button()` (button), `_draw_divider()` (divider, вариант E) и
   autosize текста (`text_block_size()`); все остальные типы проходят
   общий путь `_draw_border()` + `_draw_content()`.
2. `meta` — устоявшийся механизм расширенных свойств (0051): `fill`
   (FILL_TYPES: box/header/footer/sidebar/content/grid/image),
   `arrow_start`/`arrow_end` (hline/vline), `text_align`/`vertical_align`;
   редактируется в панели свойств (0051–0054).
3. Вложенность доступна в UI: box как контейнер — drag re-parenting с
   live-превью (0035/0038/0039), clip детей в превью, каскадное удаление,
   глубокая вложенность (d342366).
4. Типоспецифичная логика на фронте — `_blockDefaults()` в `editor.js`
   (`button` 16×1, `hline` 20×1, `vline` 1×5, `divider` 20×1, `text`
   fit-размер, остальное 20×3).
5. Типоспецифичная логика на бэкенде — принудительная толщина линий,
   autosize текста (точный fit) и autosize divider (только роста,
   `divider_fit_size()`) в `LayoutService` + дефолтная рамка
   (`default_border_style`: text → none).
6. API принимает любую строку в `block_type` и `border_style` — валидации
   нет.
7. Класс `block-{type}` в HTML-превью не стилизован в CSS — мёртвые
   классы (генерируются в `to_html_preview()`/`_block_preview_html()`).
8. Покрытие тестами: `hline`/`vline` — 10+ специфичных тестов; `button` —
   полный набор по 0022 (все высоты + стили, parity); `text` — autosize
   (0049); `divider` — полный набор по варианту E (todo-0003: ASCII,
   autosize-рост, HTML-сегменты, API, store, parity); `box` — только
   общие; `grid`, `image`, `input`, `textarea`, `sidebar`, `footer`,
   `header` — специфичных тестов нет.

# Замечания

1. Формат псевдографики (box-drawing символы) не менять — это ядро продукта.
2. Удаление типа из `BLOCK_TYPES` не ломает существующие макеты:
   `block_type` в БД — свободная строка, рендерер для неизвестных типов
   падает на общий путь отрисовки.
3. E2e-тесты на палитру: `test_drag_drop.py::test_palette_buttons_are_draggable`
   берёт число кнопок из `len(BLOCK_TYPES)` (автоматически подстроится),
   но в `test_editor.py` число кнопок статической палиты захардкожено
   (14) — при удалении типов править оба места.
4. Если `grid` реализуется, параметры сетки (число колонок/рядов) разумно
   хранить в `meta` — это устоявшееся место расширенных свойств
   (fill/стрелки/выравнивание уже там).
5. Расхождение ASCII/превью для `button` устранено задачей 0022: форма
   зависит от высоты в обоих рендерерах (parity-тесты).
