# Суть проблемы

`divider` дублирует роль `hline`, но рендерится как обычный блок с полной
рамкой (дефолт 20×3, hint `[divider]`) — особой отрисовки нет (пробел
зафиксирован в 0014, замечание 1; повторный аудит 2026-10-22 в todo-0001).
В бэклоге (todo-0001, приоритет 1) открыто решение: «убрать из
`BLOCK_TYPES` (роль закрывает `hline`) или дать отрисовку линии».

2026-10-22 проведено дизайн-обсуждение: рассмотрены варианты от удаления
до полноценного labeled divider с многострочной подписью. Документ
фиксирует все варианты с трейд-оффами для будущего выбора и реализации.

# Задача

Выбрать и реализовать дизайн `divider` так, чтобы каждый тип в палитре был
осмысленным: либо тип убирается (роль закрывает `hline`), либо получает
характерную отрисовку. Закрыть пункт todo-0001 «`divider`: решение — убрать
из `BLOCK_TYPES` (роль закрывает `hline`) или дать отрисовку линии;
обновить палитру и тесты».

# Варианты

## Вариант 1 — убрать из `BLOCK_TYPES` (минимальный)

`hline` закрывает роль полностью: 4 стиля (─┄┈═), стрелки, `none` =
невидимость. Удаление не ломает макеты: `block_type` в БД — свободная
строка, неизвестные типы падают на общий путь отрисовки (рендерятся как
box).

- Правки: `models/block.py`, `core/renderer.js` (константа),
  `tests/e2e/test_editor.py` (захардкожено 14 кнопок статической палиты),
  README, AGENTS.md.
- Опционально: разовый скрипт-миграция существующих `divider` → `hline`
  (в `tmp/`).
- Минус: существующие `divider` в макетах останутся «мёртвыми» box'ами
  с hint'ом `[divider]`.

## Вариант 2 — алиас `hline` (линия без роли)

Рендер идентичен `hline`: 1 строка, стили, стрелки, `none`.

- Полное дублирование: два имени одного компонента в палитре.
- Breaking-изменение вывода для существующих 20×3 `divider` (станут
  линиями).
- Дублирование — исходная проблема, вариант слабый. Не рекомендуется.

## Вариант 3 — labeled divider (одна строка)

`divider` получает роль, которую `hline` по определению не может:
**`hline` игнорирует контент, а `content` у `divider` — подпись на линии**
— разделитель секций с заголовком, стандартный UI-паттерн
(`──────  or  ──────`). Для AI-readable формата это ещё и семантическая
граница секций, а не просто геометрия.

Спека:

- **Толщина:** `height=1` принудительно (как у `hline` — те же места в
  `LayoutService`: create/update/replace).
- **Стиль:** `border_style` → символ линии (─┄┈═), `none` → невидим
  (последовательно с линиями).
- **Контент = подпись:**
  - пустой → обычная линия (совпадает с `hline`);
  - непустой → подпись с отступом от линии (см. подварианты по
    многострочности);
  - длиннее ширины → обрезается, линия сжимается;
  - `meta.text_align` (left/center/right) — позиция подписи, дефолт
    center (механизм есть, `divider` уже в списке типов для `text_align`
    в `properties.js`).
- **Стрелки:** не применяются (подпись — характерная черта).
- **Fill:** не применяется (`divider` не в `FILL_TYPES`).
- **HTML-превью:** CSS-линия (`.block-line--h`) + подписанный span.

### Подварианты обработки многострочного контента

Контент редактируется textarea'м — пользователь может ввести переносы.
При `height=1` у подписи одна строка:

- **A. Первая строка** — `content.splitlines()[0]`, остальное игнорируется.
  Прецедент: `button` («label — одна строка: newlines are ignored and the
  text is truncated to the inner width»). Минус: потеря данных.
- **B. Рост высоты** (autosize как у `text`). Не рекомендуется: это другой
  компонент (заголовок секции с линиями сверху/снизу), ломает инвариант
  «линия = 1 строка», наступает на `header`/`box`. (Развитие — вариант D.)
- **C. Whitespace-коллапс** (рекомендация обсуждения 2026-10-22) —
  `label = content.replace("\n", " ").strip()`; пустой результат → линия
  без подписи. Без потери данных, инвариант h=1 держится. Бонус:
  HTML-превью схлопывает переносы в пробелы само — ASCII-рендерер
  побайтово согласован с естественным поведением превью.

| Подвариант | `or\nand` | Потеря данных | Прецедент |
|---|---|---|---|
| A — первая строка | `or` | да | `button` (newlines ignored) |
| B — рост высоты | 2 строки | нет | `text` autosize (ломает h=1) |
| C — пробелы | `or and` | нет | HTML whitespace collapsing |

## Вариант D — многострочная подпись, autosize высоты («hline + text»)

Не схлопывать переносы, не терять текст, но и не фиксировать h=1:
подпись рисуется на сетку **как есть** — переносы и пробелы сохраняются.
По сути, на `hline` наложен `text` (autosize). Инвариант `height=1`
отбрасывается для подписанных divider'ов (остаётся для пустых).

Спека:

- **Пустой контент** → обычная линия, `height=1` (поведение `hline`).
- **Непустой контент** → autosize высоты: `height = число строк`
  (пересчёт при изменении контента, как у `text` 0049; ручной resize
  сохраняется до следующего изменения контента). Ширина — под контролем
  пользователя (дефолт 20), подпись обрезается по ширине.
- **Линия:** средняя строка блока (для чётной h — верхняя средняя,
  конвенция `button`), на всю ширину, символ по `border_style`,
  `none` → невидима.
- **Подпись:** рисуется как есть — переносы и пробелы сохраняются, без
  переноса слов и схлопывания. Клетки подписи перекрывают клетки линии
  (контент выигрывает). Собственные пробелы подписи «раздвигают» линию —
  зазор между линией и текстом задаётся пробелами в контенте (пробелы
  важны в псевдографике).
- **`meta.text_align`** — горизонтальное положение подписи (дефолт
  center). `vertical_align` — не применяется (подпись центрируется на
  линии). Стрелки и fill — не применяются.

Примеры (width 20):

`content = "or"`:

```
──────────or──────────
```

`content = "  or  "` (пробелы раздвигают линию):

```
──────  or  ──────
```

`content = "line one\nline two"` (h=2, линия на верхней средней):

```
──────line one──────
      line two
```

`content = "a\nbb\nccc"` (h=3, линия посередине):

```
         a
────────bb────────
        ccc
```

HTML-оверлей: CSS-линия (`.block-line--h`) не на верхней, а на средней
строке блока (offset по `top`); подпись в оверлее не нужна — она в
ASCII-слое (канвас — `white-space: pre`, переносы и пробелы видны
«как есть»).

# Сравнение вариантов

| | 1 — убрать | 2 — алиас | 3 — labeled (1 строка) | D — многострочная подпись |
|---|---|---|---|---|
| Палитра | 13 типов | 14 (два имени одного) | 14, каждый осмыслен | 14, каждый осмыслен |
| Роль | закрывает `hline` | дублирует `hline` | разделитель секций с подписью | разделитель секций с многострочной подписью |
| Breaking-вывод | нет (старые `divider` → box) | да (20×3 → линия) | да (20×3 → линия) | да (20×3, пустой контент → линия) |
| Инвариант h=1 | — | да | да | только для пустого контента |
| Объём работ | минимальный | небольшой | средний | средний+ (autosize, средняя строка) |
| Рекомендация | при приоритете минимализма | нет | да (базовый labeled) | да (если нужна многострочная подпись) |

Рекомендация обсуждения 2026-10-22: **вариант 3** (с подвариантом C для
многострочного контента), если приоритет — осмысленная палитра;
**вариант 1**, если приоритет — минимализм. Пользователь углубился в
многострочную подпись → **вариант D** как развитие; финальное решение
не принято.

# Исследование (факты из кода, 2026-10-22)

1. `divider` сейчас — общий путь: `_draw_border()` + hint `[divider]`,
   дефолт 20×3, `border_style=solid`.
2. Вся линейная механика — только у `hline`/`vline`: `_draw_line()`
   (стили ─┄┈═/│┆┊║, стрелки заменяют крайние клетки), `LayoutService`
   принудительно держит толщину 1 (create/update/replace), min-height
   resize в `editor.js`.
3. `hline` игнорирует контент (`test_line_ignores_content`).
4. `button` — прецедент однострочного label: newlines игнорируются,
   обрезка по внутренней ширине; label по центру по вертикали (верхняя
   средняя строка для чётной h).
5. `text` — прецедент autosize: `text_block_size()`, пересчёт при
   изменении контента, ручной resize сохраняется до следующего изменения
   контента; рамка по умолчанию `none`.
6. `meta.text_align`/`vertical_align` — устоявшийся механизм (0051–0054);
   `divider` уже в списках типов обоих свойств в `properties.js`.
7. Стрелки (`meta.arrow_start`/`arrow_end`) — только `hline`/`vline`.
8. Fill (`meta.fill`) — `FILL_TYPES` не включает `divider`.
9. Канвас = ASCII-слой (`white-space: pre`) + CSS-оверлей; пробелы и
   переносы в ASCII-слое видны «как есть».
10. HTML-превью: `hline`/`vline` → `.block-line--h/--v`; контент блоков
    в оверлее не дублируется (живёт в ASCII-слое).
11. E2e: `test_editor.py` захардкожено 14 кнопок статической палитры
    (2 места); `test_drag_drop.py` берёт `len(BLOCK_TYPES)`
    (автоматически подстраивается).
12. Существующие упоминания `divider` в тестах: `test_renderer.py`
    (общая матрица типов + fill-матрица), `tests/js/test_renderer.js`
    (то же), `test_js_renderer_parity.py` (fill-матрица).
