# Суть проблемы

`footer` — «только имя» (аудит todo-0001, 2026-10-22): отрисовка
идентична `box` (общий путь `_draw_border()` + `_draw_content()`),
дефолт 20×3 с текстом `[footer]`, характерной отрисовки нет. Зеркальная
задача к `header`-attach (todo-0007, реализован в 0074, коммит 2e3bacd):
когда `footer` вставлен **дочерним в `box`** и прижат к нижней стороне,
он «прилипает» к низу — отключаются нижняя, левая и правая стороны
рамки, остаётся только верхняя, и она соединяется (junction) с рамкой
`box`. Визуально `footer` «сидит» внизу содержимого `box`, отделённый
от него линией:

```
┌────────────────┐
│                │
│                │
├────────────────┤
│ footer         │
└────────────────┘
```

# Задача

Дать `footer` характерную отрисовку в режиме «приклеен к низу `box`»:
без нижней/левой/правой рамки, только верхняя линия на всю внутреннюю
ширину `box` и junctions с рамкой `box`. Закрыть пункт todo-0001 по
`footer` (приоритет 2). Одновременно **унифицировать** код
attached-рендера с `header` (решение 2026-11-05) — общий алгоритм,
сторона выводится из типа; подготовка к прилипанию `sidebar`
(отдельная спека, follow-up).

# Варианты

## Вариант 1 — геометрический, проверка по `y + h` (рекомендация)

`footer` в режиме «attached», когда его **относительная**
`y + h >= inner_h` (нижний край на уровне нижней внутренней границы
`box` или ниже). `x` и `width` **не проверяются**. Родитель — только
`box` (`grid` вне scope, как в todo-0007).

- **Эффективная геометрия (выводится при рендере):** `x=0`,
  `y = inner_h − h` (относительные), `width` = внутренняя ширина `box`
  (`bw−2`), `height` = сохранённая. Сохранённые `x`/`y`/`width`
  игнорируются, пока `footer` приклеен; они важны только когда
  `footer` отклеен (`y + h < inner_h`) — тогда он рендерится как
  обычный `box` в сохранённой позиции/ширине.
- Это render-time вывод (как перегородки `grid`, todo-0005, и как
  `header`-attach, todo-0007), а не изменение данных. При resize `box`
  `footer` автоматически следует за шириной и нижней границей —
  сохранённые данные не трогаются.
- **Обратная совместимость:** старый макет, где `footer` лежит прижатым
  к низу `box`, будет рендериться иначе (без трёх сторон рамки).
  В отличие от `header` (случайное `y=0` — редко), это **каноничный**
  лейаут — риск выше. Принято как исключение из правила обратной
  совместимости (решение 2026-11-05, см. замечание 2).

## Вариант 2 — флаг в `meta`

`meta.attach: "bottom"`, ставится при вставке.

- Плюсы: строгая обратная совместимость, состояние явное.
- Минусы: флаг может «протухнуть» (перемещённый `footer` висит
  посреди `box` без трёх сторон рамки — выглядит сломанно); нужна
  UI-точка управления флагом; больше кода; расхождение с уже
  реализованным геометрическим `header`-attach (два механизма для
  зеркального поведения). Отклонён (как в todo-0007).

## Сравнение

| | 1 — геометрический (y+h) | 2 — флаг |
|---|---|---|
| Условие | 1 проверка (`y+h>=inner_h`) | флаг в `meta` |
| Обратная совместимость | каноничный лейаут рендерится иначе (принято) | строгая |
| Переприклеить после drag | просто (достаточно `y+h>=inner_h`) | нужен флаг |
| Узкий `footer` | нет — всегда на всю ширину | нет |
| Согласованность с header | да (один механизм) | нет |
| Объём кода | меньше | больше (флаг + UI + stale) |
| Рекомендация | **да** | нет |

# Ключевые решения (согласованы 2026-11-05)

1. **Условие:** относительная `y + h >= inner_h`; родитель — только
   `box` (`grid` вне scope). `x`/`width` не проверяются.
2. **Растяжение:** приклеенный `footer` всегда на всю внутреннюю
   ширину `box` — узкого `footer` нет. Эффективная геометрия
   `x=0, y=inner_h−h, w=inner_w`.
3. **Стиль линии:** свой `border_style` `footer`'а; junctions —
   стандартные `├`/`┤` (style map родителя), как в `grid` (0063) и
   `header`-attach (todo-0007).
4. **Родитель без рамки** (`border_style=none`): attached-режим
   работает, но junctions нет (линия просто заканчивается `─`).
5. **Дефолтная высота:** 3 (текущий дефолт, не меняется).
6. **Sticky при resize `box`:** `footer` следует за шириной и нижней
   границей (render-time), сохранённые данные не трогаются.
7. **`grid` как родитель:** вне scope — `footer` внутри `grid`
   рендерится как сейчас (общий путь).
8. **Resize приклеенного `footer`:** сохранённые `x`/`y`/`width`
   игнорируются, пока приклеен, применяются после отклейки
   (`y + h < inner_h`). При resize высоты нижний край зафиксирован
   (приклеен), верхний ходит.
9. **Унификация с `header` (решение 2026-11-05):** общий
   attached-алгоритм, сторона (top/bottom) выводится из
   `block_type` — `header`→top, `footer`→bottom. Существующие
   header-функции переименовываются в нейтральные (см. план работ).
   Флаг `RenderBlock.attached` не меняется — сторона имплицитна из
   типа. Мотивация: алгоритм идентичен до флипа y, поверхность
   parity (Python↔JS) не удваивается; подготовка к `sidebar`
   (follow-up).
10. **Обратная совместимость:** принято как исключение — каноничный
    лейаут (footer внизу box) рендерится иначе. Зафиксировано
    2026-11-05.
11. **Авто-прилипание при сжатии `box`:** если сжатие `box` по высоте
    делает `y + h >= inner_h` — `footer` приклеивается автоматически
    (асимметрия с `header`: его условие `y <= 0` не зависит от размера
    `box`). Принято **временно**, уточняется после тестирования
    готовой реализации (решение 2026-11-05).
12. **`h > inner_h`:** `footer` приклеен всегда (условие
    выполняется при любом `y >= 0`), верхняя линия клипнута
    (строка линии выше внутренней области) — нижнюю границу
    визуально задаёт рамка `box`.
13. **Точное касание:** `y + h == inner_h` → приклеен (зеркало
    `y == 0` у `header`).

# Правила рендера

Обозначения: родитель-`box` — абсолютные `(px, py)`, размер
`(pw, ph)`. Внутренняя область — `x ∈ [px+1, px+pw−2]`,
`y ∈ [py+1, py+ph−2]`; `inner_w = pw−2`, `inner_h = ph−2` (1-cell
padding — безусловный, как в `_render_children_in_container`).
`footer`-ребёнок — относительные `(cx, cy)`, размер `(cw, ch)`.
**Attached** ⇔ `cx` не проверяется, `cy + ch >= inner_h`,
родитель — `box`.

Эффективная геометрия (абсолютная): `x = px+1`,
`y = py+1+inner_h−ch`, `w = inner_w`, `h = ch`.

- **Рамка:** нижней/левой/правой сторон нет.
- **Верхняя линия:** строка `py+1+inner_h−ch`, столбцы
  `px+1 .. px+pw−2` (вся внутренняя ширина). Символ —
  `border_style` `footer`'а. Рисуется, только если
  `ch <= inner_h` (строка линии внутри внутренней области) и
  `border_style != none`. При `ch > inner_h` линия клипнута
  (строка выше внутренней области) — верхнюю границу визуально
  задаёт рамка `box`.
- **Junctions:** на рамке `box` в клетках `(px, py+1+inner_h−ch)` и
  `(px+pw−1, py+1+inner_h−ch)` — `├`/`┤` (style map `box`'а).
  Рисует **родитель** (линия `footer`'а клипнута во внутреннюю
  область и не может дописать клетки рамки). Рисуется, только если
  линия рисуется (`ch <= inner_h`, `border_style footer != none`)
  **и** у `box` есть рамка (`border_style != none`).
- **Контентная область:**
  - `border_style != none` — полная ширина (`inner_w`) × `ch−1` строк
    (строки `py+2+inner_h−ch .. py+ph−2`, под линией);
  - `border_style == none` — полная ширина × `ch` строк (линии нет,
    высота полная).
  - Контент word-wrap по `inner_w` + `meta.text_align`/
    `vertical_align`; fill (`meta.fill`) заливает область; hint
    `[footer]` при пустом контенте — как у `box`.
- **`ch == 1`** (`border_style != none`) — контентная область 0 строк,
  `footer` = только линия (разделитель, приклеенный к низу).

Примеры (box 20×8, внутренняя 18×6; `footer` h=3, content `[footer]`,
`y = 6−3 = 3`):

```
Приклеен (y+h >= inner_h):          Отклеен (y=1, y+h < inner_h):
┌──────────────────┐                ┌──────────────────┐
│                  │                │                  │
│                  │                │ ┌──────────────┐ │
├──────────────────┤                │ │ [footer]     │ │
│ [footer]         │                │ └──────────────┘ │
│                  │                │                  │
│                  │                │                  │
└──────────────────┘                └──────────────────┘
```
