# Суть проблемы

`sidebar` — «только имя» (аудит todo-0001, 2026-10-22): отрисовка
идентична `box` (общий путь `_draw_border()` + `_draw_content()`),
дефолт 20×3 с текстом `[sidebar]`, характерной отрисовки нет.
Последний из группы «только имя» — `content` закрыт (todo-0004),
`grid` (todo-0005), `header` (todo-0007/0074), `footer`
(todo-0008/0075).

Предлагаемая доработка (прямое зеркало `header`/`footer`, follow-up из
todo-0008): когда `sidebar` вставлен **дочерним в `box`** и прижат к
левому **или** правому краю, он «прилипает» — отключаются внешние три
стороны рамки, остаётся только внутренняя **вертикальная** линия на
всю внутреннюю высоту `box`, соединённая (junction) с верхней и нижней
рамкой `box`. Визуально `sidebar` «сидит» сбоку содержимого `box`,
отделённый от него линией:

```
прилип слева:                   прилип справа:
┌──────┬────────────┐           ┌────────────┬──────┐
│[side │            │           │            │[side │
│bar]  │            │           │            │bar]  │
│      │            │           │            │      │
│      │            │           │            │      │
└──────┴────────────┘           └────────────┴──────┘
```

Отличие от `header`/`footer`: у тех сторона «зашита» в тип (`header` →
верх, `footer` → низ). `sidebar` — **один** тип, сторона (left/right)
выводится из геометрии (какой край отсечён).

# Задача

Дать `sidebar` характерную отрисовку в режимах «приклеен к левому
краю `box`» и «приклеен к правому краю `box`»: без трёх внешних сторон
рамки, только внутренняя вертикальная линия на всю внутреннюю высоту
`box` и junctions `┬`/`┴` с верхней/нижней рамкой. Закрыть пункт
todo-0001 по `sidebar` (приоритет 2). Расширить унифицированный
attached-рендер (`_draw_attached` / `_draw_attached_junctions`,
сторона из типа) на `left`/`right`.

# Варианты

## Вариант 1 — геометрический, сторона выводится из отсечения (рекомендация)

`sidebar` в режиме «attached», когда его **относительная** левая сторона
рамки отсечена левым краем `box` (`x < 0` → прилип к **левому** краю)
**или** правая сторона отсечена правым краем (`x + w > inner_w` →
прилип к **правому**). `y` и `height` **не проверяются**. Родитель —
только `box` (`grid` вне scope, как todo-0007/0008). Зеркало условия
`header` (`y < 0`) / `footer` (`y + h > inner_h`) по горизонтали.

- **Эффективная геометрия (render-time вывод):** прилип слева —
  `x = 0`, `y = 0`, `width` = сохранённая, `height = inner_h`. Прилип
  справа — `x = inner_w − w`, `y = 0`, `width` = сохранённая,
  `height = inner_h` (все величины относительные). Сохранённые
  `x`/`y` игнорируются, пока приклеен (высота всегда полная); они
  применяются, когда `sidebar` отклеен (`0 <= x` и `x + w <= inner_w`)
  — тогда обычный `box` в сохранённой позиции/размере.
- Это render-time вывод (как перегородки `grid`, todo-0005, и как
  `header`/`footer`-attach), а не изменение данных. При resize `box`
  `sidebar` следует за высотой — данные не трогаются.
- **Обратная совместимость:** старый макет, где `sidebar` *случайно*
  лежит с `x < 0` или прижатым к правому краю, будет рендериться иначе
  (без трёх сторон рамки). Формальное отклонение от правила обратной
  совместимости — согласовать как исключение (см. замечание 2).

## Вариант 2 — сторона в `meta` (`meta.side` / `meta.attach`)

`meta.side: "left" | "right"` (или `meta.attach`) ставится при вставке.

- Плюсы: строгая обратная совместимость; сторона явная (нет
  неоднозначности при `x < 0` и `x + w > inner_w` одновременно — см.
  решение 2).
- Минусы: флаг может «протухнуть» (перемещённый `sidebar` висит посреди
  `box` без трёх сторон — выглядит сломанно); нужна UI-точка
  управления; больше кода; расхождение с уже реализованным
  геометрическим `header`/`footer`-attach (два механизма для
  зеркального поведения). Отклонён как основной (как в todo-0007/0008);
  не исключается как **opt-in переопределение** поверх геометрии
  позднее (см. замечание 5).

## Вариант 3 — два типа `sidebar_left` / `sidebar_right`

Зеркалит разбиение `header`/`footer` (сторона «в типе»), сторона не
выводится.

- Минусы: удваивает `BLOCK_TYPES`/палитру/дефолты; ломает обратную
  совместимость старого `sidebar`; размывает концепцию «одна боковая
  колонка». Отклонён.

## Сравнение

| | 1 — геометрический (сторона из `x`) | 2 — флаг `meta.side` | 3 — два типа |
|---|---|---|---|
| Условие | 2 проверки (`x<0` / `x+w>inner_w`) | флаг в `meta` | тип |
| Обратная совместимость | `sidebar` у края рендерится иначе (редко) | строгая | ломает старый тип |
| Переприклеить после drag | просто | нужен флаг | — |
| Неоднозначность обоих краёв | нужен tie-break (решение 2) | решается флагом | решается типом |
| Согласованность с header/footer | да (один механизм) | нет | частично |
| Объём кода | меньше всех | больше | больше |
| Рекомендация | **да** | opt-in позже | нет |

# Ключевые решения (предложены — требуют согласования)

1. **Условие:** относительные `x < 0` → прилип к левому краю;
   `x + w > inner_w` → к правому. `y`/`height` не проверяются;
   родитель — только `box` (`grid` вне scope).
2. **(открыто) Оба края отсечены** (`w > inner_w`: `x < 0` **и**
   `x + w > inner_w` одновременно — `sidebar` шире внутренней области):
   какая сторона побеждает? Предложено по умолчанию — **левый край**
   (первый по приоритету). Альтернативы: больший размер отсечения;
   сторона, к которой ближе центр блока. **Закрыть до реализации.**
3. **Растяжение:** приклеенный `sidebar` всегда на всю внутреннюю
   **высоту** `box` — низкой боковой колонки нет (зеркало «узкого
   `header` нет»). Эффективная геометрия см. вариант 1.
4. **Стиль линии:** свой `border_style` `sidebar`'а (вертикальный
   символ `v`); junctions — `┬` (`t_t` на верхней рамке) / `┴` (`b_l`
   на нижней) из style map **родителя**, как `├`/`┤` у `header`/`footer`
   и frame-узлы `grid` (0063).
5. **Родитель без рамки** (`border_style=none`): attached-режим
   работает, но junctions нет (линия просто заканчивается вертикальным
   символом у границы внутренней области).
6. **Дефолт ширины:** 20 (текущий дефолт, не меняется). **(открыто)**
   Для узкой высокой колонки дефолт `20×3` выглядит странно; обсудить
   смену дефолта `sidebar` на узкий/высокий (напр. `10×12`) —
   затрагивает палитру и обратную совместимость дефолтов.
7. **Sticky при resize `box`:** `sidebar` следует за высотой (render-
   time), сохранённые данные не трогаются.
8. **`grid` как родитель:** вне scope — `sidebar` внутри `grid`
   рендерится как сейчас (общий путь box).
9. **Resize приклеенного `sidebar`:** сохранённые `x`/`y` игнорируются,
   пока приклеен, применяются после отклейки. Ширина сохраняется и
   используется; приклеен к внешнему краю — внутренний край ходит.
10. **Дефолты выравнивания контента:** **(открыто)** `box` — top/left,
    `header` — center/middle. Для боковой колонки предложен **top/left**
    (как `box`, а не как `header`). Подтвердить.
11. **Унификация кода:** расширить существующий attached-рендер на
    `left`/`right` (сторона уже выводится из типа у `header`/`footer`);
    для `sidebar` сторона берётся не из типа, а из геометрии —
    `RenderBlock` нуждается в явном поле стороны (`side ∈ {left,right}`)
    либо булевом `attached_left`, т.к. тип один. Решить в плане.
12. **`w > inner_h`-аналог:** `w > inner_w` (шире внутренней области) →
    приклеен всегда, внутренняя линия клипнута (выходит за горизонталь
    внутренней области) — левую/правую границу визуально задаёт рамка
    `box` (зеркало `ch > inner_h` у `header`/`footer`).

# Правила рендера

Обозначения: родитель-`box` — абсолютные `(px, py)`, размер
`(pw, ph)`. Внутренняя область — `x ∈ [px+1, px+pw−2]`,
`y ∈ [py+1, py+ph−2]`; `inner_w = pw−2`, `inner_h = ph−2` (1-cell
padding безусловный, как в `_render_children_in_container`).
`sidebar`-ребёнок — относительные `(cx, cy)`, размер `(cw, ch)`.
**Attached-левый** ⇔ `cx < 0`; **attached-правый** ⇔ `cx + cw > inner_w`;
`cy`/`ch` не проверяются; родитель — `box`.

Эффективная геометрия (абсолютная):
- левый: `x = px+1`, `y = py+1`, `w = cw`, `h = inner_h`;
- правый: `x = px+1+inner_w−cw`, `y = py+1`, `w = cw`, `h = inner_h`.

- **Рамка:** трёх внешних сторон нет. **Линия** — внутренняя
  вертикальная: у левого — **правая** колонка эффективного
  прямоугольника (`x+cw−1`), у правого — **левая** колонка (`x`).
  Строки `py+1 .. py+ph−2` (вся внутренняя высота). Символ —
  `border_style` `sidebar`'а (`v`). Рисуется, только если
  `cw <= inner_w` (колонка линии внутри внутренней области) и
  `border_style != none`. При `cw > inner_w` линия клипнута — рамка
  `box` задаёт границу.
- **Junctions:** на рамке `box` в клетках `(lx, py)` — `┬` (`t_t`) и
  `(lx, py+ph−1)` — `┴` (`b_l`), где `lx` — колонка линии. Рисует
  **родитель** (линия `sidebar`'а клипнута во внутреннюю область и не
  может дописать клетки рамки; паттерн 0063). Рисуется, только если
  линия рисуется (`cw <= inner_w`, `border_style != none`) **и** у `box`
  есть рамка. При совпадении колонки линии с внутренней боковой
  колонкой junctions заменяют верхнюю/нижнюю `─` рамки — корректно.
- **Смешанные junctions:** при несовпадении стиля вертикальной линии и
  горизонтальной рамки `box` — Unicode `╤`/`╥` (верхняя рамка) и
  `╧`/`╨` (нижняя); таблица (box_style, child_style):
  верх — `{double,solid}→╥`, `{solid,double}→╤`; низ —
  `{double,solid}→╧`, `{solid,double}→╨`. Dashed/dotted → fallback на
  style map `box`'а (нет dashed-junctions), как в
  `_mixed_attached_junction`. **Новые таблицы** `╤╥╧╨` (существующие
  `╞╡╟╢` — для горизонтальной линии `header`/`footer`).
- **Контентная область:**
  - `border_style != none` — `cw−1` колонок по другую сторону линии
    (левый: столбцы `px+1 .. x−1`; правый: `x+1 .. px+pw−2`) × полная
    внутренняя высота (`inner_h`);
  - `border_style == none` — `cw` колонок × `inner_h` (линии нет).
  - Контент word-wrap по ширине области + `meta.text_align`/
    `vertical_align`; fill (`meta.fill`) заливает область; hint
    `[sidebar]` при пустом контенте — как у `box`.
- **`cw == 1`** (`border_style != none`) — контентная область 0
  колонок, `sidebar` = только линия (вертикальный разделитель,
  приклеенный к краю).

Примеры (box 20×8, внутренняя 18×6; `sidebar` w=6, content
`[sidebar]`, `cw−1 = 5` для текста):

```
Прилип слева (x<0):             Прилип справа (x+w>inner_w):
┌─────┬────────────┐            ┌────────────┬─────┐
│[side│            │            │            │[side│
│bar] │            │            │            │bar] │
│     │            │            │            │     │
│     │            │            │            │     │
│     │            │            │            │     │
│     │            │            │            │     │
└─────┴────────────┘            └────────────┴─────┘

Отклеен (0<=x, x+w<=inner_w — обычный box):
┌──────────────────┐
│ ┌────┐           │
│ │[si │           │
│ │de  │           │
│ └────┘           │
│                  │
└──────────────────┘
```
