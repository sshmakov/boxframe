# Суть проблемы

Правило marquee-выделения (введено в 0033) — «пересечение»: блок
выделялся, если рамка пересекала его область, даже если закрывала одну
клетку из десятков. При выборе группы элементов это давало неожиданные
результаты: рядом стоящие блоки, слегка задетые рамкой, попадали в
выделение, и точечно выделить именно нужную группу было невозможно.

# Задача

Изменить правило выделения группы элементов мышью: блок выделяется,
только если он **полностью** внутри marquee-рамки; частичное пересечение
не выделяет.

# Исследование

1. **Правило живёт в одном месте** — `_marqueeHits()` в `editor.js`.
   Работает с плоским списком блоков и «сырыми» координатами `x/y`
   (у детей — относительные, как в БД); эта семантика не менялась,
   заменено только условие.
2. **Рамка — дробные grid-координаты.** `_marqueeGridRect()` считает
   углы через `_contentToGrid()` — чистое деление пикселей на
   `charWidth/charHeight`, без округления. Если край рамки совпадает с
   краем блока, возможна погрешность (23.9999 vs 24.0) — в e2e рамку
   берут с запасом 1–2 клетки.
3. **Старые e2e-прямоугольники перестали подходить.** Тесты использовали
   `TWO_BOXES`: A (2,2) 10×4 (до x=12, y=6) и B (14,2) 10×4 (до x=24,
   y=6). Рамка (1,1)→(22,5) пересекала оба блока, но по новому правилу
   не содержит ни один (у A низ y=6 > 5, у B правый край x=24 > 22) —
   прямоугольник расширен до (1,1)→(26,8).
4. **Канвас по умолчанию 80×24** (`DEFAULT_CANVAS_WIDTH/HEIGHT`),
   поэтому концы рамки надёжно внутри канваса и не триггерят
   auto-scroll при drag.
5. **Спецификация 0033 правило не фиксирует** — там только «рамка на
   пустом канвасе», поэтому менять спецификации не потребовалось.

# Замечания

1. **E2E-рамки должны строго превышать bounding box блоков.** Из-за
   дробных координат рамки (без округления) тесты, где край рамки
   совпадает с краем блока, могут быть флейковыми; держать запас
   1–2 клетки.
2. **Marquee не учитывает вложенность.** Вычисление по плоскому списку с
   относительными координатами детей — семантика та же, что до
   изменения правила. Если в будущем выделение начнёт учитывать
   контейнеры, `_marqueeHits()` придётся переводить на абсолютные
   координаты.
3. **E2E требует запущенный сервер на :8000** и запуск отдельно от
   API-тестов (playwright sync API конфликтует с pytest-asyncio в одном
   процессе).
