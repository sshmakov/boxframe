# Суть проблемы

`box` объявлен в `BLOCK_TYPES` как «Generic container», модель данных уже
поддерживает вложенность (`Block.parent_id`, `children` с
`cascade="all, delete-orphan"`), но в редакторе `box` контейнером не
является:

- из UI невозможно создать дочерний блок: drop из палитры всегда создаёт
  корневой блок (`createBlock` без `parent_id`), перетаскивание блока
  двигает его в абсолютных координатах канваса без re-parenting;
- HTML-превью флаттнит детей на тот же слой и позиционирует их по их
  собственным x/y (относительным, а не абсолютным) — ребёнок с
  относительными (1,1) у родителя (10,10) рисуется в (1,1), т.е. в
  левом верхнем углу канваса; отсечения рамкой контейнера в превью нет;
- hit-testing в редакторе (`onCanvasMouseDown`) сверяет курсор с
  `b.x/b.y` — для детей это относительные координаты, поэтому ребёнок
  фактически не выделяется в своём видимом положении;
- при перемещении/ресайзе родителя дети следуют за ним в ASCII-рендере
  (относительные координаты), но не следуют в превью;
- при удалении контейнера дети удаляются в БД (ORM-каскад), но в локальном
  списке редактора (`this.blocks`) остаются как stale-записи до следующей
  полной загрузки.

Итог: вложенность существует в модели, рендерере и экспорте, но
недостижима из редактора и расходит между ASCII и HTML-представлениями.

# Задача

Сделать `box` контейнером в редакторе:

1. **Drop в box** — элемент, добавленный (drop из палитры) в область `box`,
   становится его дочерним: `parent_id` = id box, x/y — относительные
   координаты внутри контейнера.
2. **Drag в box** — перетаскиваемый существующий элемент, отпущенный над
   `box`, становится его дочерним (re-parenting с переводом координат в
   относительные). Перетаскивание из контейнера на канвас возвращает
   элемент в корень (перевод координат в абсолютные).
3. **Отсечение (clip)** — видимость дочерних элементов отсекается
   контейнером: в превью контейнер обрезает вылезших детей
   (`overflow: hidden`), в ASCII дети не рисуются за рамкой контейнера
   (clamp уже есть — проверить и зафиксировать тестами).
4. **Сохранение положения** — при перемещении и ресайзинге контейнера дети
   сохраняют своё положение внутри него (относительные координаты; при
   ресайзе дети не перераскладываются — остаются на своём относительном
   месте, при нехватке места клипаются).
5. **Каскадное удаление** — удаление контейнера удаляет его детей (в ORM
   уже есть; синхронизировать локальный список редактора).

# Исследование

Аудит текущего состояния (2026-09-20):

| Слой | Вложенность |
|---|---|
| Модель (`models/block.py`) | `parent_id` — self-ref FK; `children` с `cascade="all, delete-orphan"` — каскадное удаление работает на уровне ORM |
| Сервис (`layout_service.py`) | `create_block`/`batch_blocks`/`replace_blocks` принимают `parent_id`; `delete_block` опирается на ORM-каскад |
| Рендерер (Python + JS) | дети рисуются внутри родителя с 1-cell padding, w/h клампятся во внутренний размер (`min(child.w, parent.w - 2)`) — частичный клип в ASCII есть |
| HTML-превью | дети флаттнятся на тот же слой и позиционируются по своим (относительным) x/y — неверное положение, отсечения нет |
| Редактор (`editor.js`) | `this.blocks` — плоский список; создать детей из UI невозможно; hit-testing в абсолютных координатах (для детей сломан); `deleteBlock` оставляет детей в локальном списке |
| Импорт (`core/import.js`) | разбирает nested-формат экспорта в плоский список с `parent_id` |
| Экспорт | JSON — nested (корни + children) |

Ключевые факты:

1. x/y детей хранятся относительными к родителю (рендерер прибавляет
   позицию родителя + 1-cell padding). Перемещение/ресайз родителя в БД
   не требует правки детей — в ASCII-рендере они следуют автоматически.
2. Расхождение — в превью и редакторе: превью флаттнит детей с
   относительными координатами (ребёнок рисуется в левом верхнем углу
   канваса), hit-testing не учитывает родителя.
3. Тип `box` в рендерере не особенный — детей может держать любой тип с
   рамкой; задача — сделать контейнерным поведение в редакторе
   (drop/drag/re-parenting), а не в рендерере.
4. `canvas_size` (Python + JS) уже учитывает детей с padding.
5. Полное видение контейнера (padding/margin, align/justify,
   stretch/percent/flex, overflow clip/shrink/scroll/wrap, порядок
   layout-pass) описано в Obsidian-файле — отдельная большая задача.

# Выполнение задачи

Выполнено (2026-09-20). Итог: `box` — полноценный контейнер в редакторе;
вложенность достижима из UI, ASCII и HTML-представления согласованы.

## Редактор (editor.js)

- `_absoluteRect(block)` — абсолютные координаты блока (ход по цепочке
  родителей, +1-cell padding на каждом уровне). Используются везде, где
  раньше были «сырые» x/y: hit-testing (mousedown, dblclick), marquee,
  оверлеи (рамка выделения, properties-панель, edit-overlay), resize,
  nudge.
- `_findDropContainer(cx, cy, excludeIds)` — внутренняя `box`, абсолютная
  область которой содержит точку (максимальная глубина); `excludeIds` —
  поддерево перетаскиваемого блока (защита от циклов).
- Drop из палитры (`onCanvasDrop`): центр падающего блока внутри `box` →
  `parent_id` + относительные координаты (abs − parentAbs − 1).
- Move drag (`_commitBlockMove`): центр блока при отпускании внутри `box`
  (кроме собственного поддерева) → re-parenting в относительные; блок с
  родителем, отпущенный вне контейнера → `parent_id: null` + абсолютные.
- `deleteBlock`/`deleteSelection`: из `this.blocks` удаляется весь
  поддерево (BFS `_subtreeIds`), а не только корень.
- `duplicateBlock`: копия сохраняет `parent_id`.

## Store / API / сервис

- `core/store.js`: `updateBlock`/`batchBlocks` всегда применяют
  `parent_id` — `null` значимое значение (un-parenting), в отличие от
  прочих null.
- `api/layouts.py`: PUT блока и batch принимают явный `parent_id`
  (включая `null`) через `model_fields_set`. `_serialize_blocks_for_html`
  сделан рекурсивным — ранее вложенность была только на один уровень, и
  web-редактор терял внуков в HTML-превью (закреплено тестом
  `test_render_nested_three_levels_html_preview`).
- `layout_service.py`: `_validate_reparent` — родитель существует и в том
  же layout; цикл запрещён (ход по цепочке предков). Применяется в
  `update_block` и `batch_blocks`.

## Рендерер (renderer.py + core/renderer.js, parity)

- HTML-превью: дети вложены в div родителя и позиционируются по
  абсолютным координатам (parentAbs + 1 + relative); у родителя
  `overflow: hidden` — отсечение вылезших детей.
- ASCII: clamp детей во внутренний размер контейнера сохранён

# Замечания

1. Формат псевдографики (box-drawing символы) не менять — это ядро
   продукта; клип в ASCII достигается тем, что дети не рисуются за
   контейнером, а не новыми символами.
2. Python- и JS-рендереры не расхожать — правки превью в обоих + оба
   набора тестов + parity.
3. Re-parenting должен запрещать циклы: блок не может стать потомком
   самого себя (drop box на собственного ребёнка — игнорировать).
4. Групповой drag (мульти-выделение) — правило re-parenting определить при
   реализации: весь группой, если все элементы над контейнером, либо
   только перетаскиваемый. **Решено:** re-parenting — только одиночный
   drag; групповой move/nudge сдвигает блоки относительным дельтой и
   не меняет `parent_id`.
5. Задача говорит о `box`, но рендерер/модель не ограничивают тип
   контейнера — логика drop/drag может работать и для других типов с
   рамкой; начать с `box`, расширение — в последующих задачах.
   **Решено:** контейнер в редакторе — только `box`
   (`_findDropContainer` фильтрует `block_type === 'box'`).
6. При конкретизации файл получает номер (следующий свободный) и переезжает
   в подпапку десятка, из backlog удаляется (см. `tasks/README.md`).
7. e2e: глобальные mouse-слушатели редактора bind-ятся в `init()` только
   после асинхронной загрузки (fetchInfo/fetchBlocks/refreshRender) —
   canvas-операции, начатые раньше, молча теряются (mousedown срабатывает,
   mousemove/mouseup — нет). В e2e перед drag/marquee ждать инициализацию
   (`_wait_editor_ready`: `!loading && blocks.length === n && charWidth > 0`).
8. `base.html` грузит HTMX с CDN (unpkg), тогда как Alpine вендорится
   локально — e2e-тесты зависят от внешней сети (при недоступном CDN
   `page.goto` висит до таймаута «load»). Кандидат на вендоринг
   `htmx.min.js` в `static/js/`.
