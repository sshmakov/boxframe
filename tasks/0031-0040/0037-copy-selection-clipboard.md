# Суть проблемы

Выделенные элементы нельзя скопировать в clipboard. Единственная кнопка Copy
в шапке копирует псевдографику всего макета, а не только выделение. Чтобы
перенести часть макета (например, блок-контейнер с вложенными детьми) в
другое место или в другой инструмент, приходится экспортировать JSON и
импортировать его обратно.

# Задача

Добавить на панель со свойствами выделенных элементов кнопку копирования:
по клику выделенные элементы **с дочерними** копируются в clipboard в
формате текста (ASCII-псевдографика — формат, выбранный пользователем).

Текст должен быть «автономным»: выделение отрисовывается заново в
координатах, где его левый верхний угол — (0,0), поэтому скопированное
можно вставить/прочитать без привязки к исходному макету.

# Исследование

1. **Формат копирования.** Варианты: JSON (вложенный экспорт, точный,
   импортируемый) и ASCII-псевдографика (человекочитаемый, нативный формат
   продукта). Пользователь выбрал ASCII.
2. **Рендер уже умеет рисовать произвольный плоский список.**
   `PGRenderer.render(blocks, width, height)` с `width/height = null`
   даёт канвас 80×24 как пол, но хвостовые пробелы/пустые строки
   срезаются — на выходе ровно bounding box нарисованного. Достаточно
   передать в него «копию» выделенного списка блоков.
3. **Координаты детей — относительные.** Блок, чей родитель НЕ входит в
   выделение, в скопированном списке становится корнем: его координаты
   нужно перевести в абсолютные (ход по цепочке родителей с 1-клеточным
   паддингом на каждом уровне — та же логика, что в `_absoluteRect`) и
   сдвинуть так, чтобы минимум по X/Y стал (0,0). Блок, чей родитель
   выделен, сохраняет относительные координаты и `parent_id` — иерархия
   и clip детей работают как в макете.
4. **Совпадения в выделении.** Выделены и родитель, и его ребёнок —
   объединение поддерев (union) берёт ребёнка один раз.
5. **Clipboard API.** `navigator.clipboard.writeText` уже используется в
   `copyRaw()` (шапка) — тот же паттерн, включая `file://`-совместимость
   static-режима (Clipboard API доступен в secure context, `file://`
   считается trusted).
6. **E2E: hit-test канваса — по координатам, не по DOM.** Клик в центр
   родителя с ребёнком попадает на ребёнка (у него выше order), поэтому
   тест кликает по верхней рамке родителя — точка внутри родителя, но
   вне ребёнка.
7. **Пустые блоки рисуют type-hint `[box]`** (как в превью на канвасе) —
   скопированный текст отражает ровно то, что видно; в узких блоках hint
   клипится и перекрывает середину нижней рамки. Зафиксировано в
   node-тестах.

# Замечания

1. **Копия — только «внешняя».** Вставить скопированную псевдографику
   обратно в редактор нельзя: импортируется только JSON. Кандидат на
   будущую задачу: парсер псевдографики (reverse renderer) или
   drag-n-drop текста на канвас.
2. **`[box]`-хинты попадают в копию.** Пустые блоки копируются с
   type-hint, как они выглядят на канвасе. Если это помешает (например,
   при вставке в документ), можно добавить флаг «без хинтов» — но тогда
   копия перестанет совпадать с превью.
3. **Дублирование маркапа панели** (см. замечание 1 в 0032) — кнопка
   добавлена в оба файла синхронно; e2e-тест
   `test_static_editor_panel_matches_web_layout` страхует от рассинхрона.
4. **`selectionToAscii` живёт в `editor.js`** как чистая функция рядом с
   приложением — при росте логики копирования (например, JSON-режим)
   имеет смысл вынести в отдельный модуль `core/copy.js` по образцу
   `core/import.js`.
