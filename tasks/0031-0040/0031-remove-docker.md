# Суть проблемы

Проект публикуется в PyPI и устанавливается через `pip install boxframe`,
но инструкция по сборке Docker (`docker build -t boxframe .`) осталась в
Quick Start README (который публикуется на страницу PyPI) и в AGENTS.md.
Инструкция не подходит к опубликованному пакету: `docker build` требует
исходников репозитория, а у пользователя wheel'а их нет. Dockerfile
остался мёртвым весом — единственный поддерживаемый способ запуска
приложения — консольный entry point `boxframe` (дефолт `127.0.0.1:8000`).

# Исследование

1. **Что попадает в публикацию.** `pyproject.toml` имеет
   `readme = "README.md"` — README отображается на странице PyPI,
   поэтому Docker-блок в Quick Start был частью публикации.
2. **Docker-сборка несовместима с pip-флоу.** `docker build -t boxframe .`
   собирает образ из исходников репозитория; пользователь
   `pip install boxframe` Dockerfile не имеет. Запуск — только через
   entry point `boxframe` (`main.py: run()`, дефолты `127.0.0.1:8000`).
3. **Исторические упоминания сохраняются.**
   `tasks/0021-0030/0029-pypi-publishing.md` упоминает Dockerfile в
   контексте задачи об упаковке — это история, она не удаляется.

# Замечания

1. **Docker — не поддерживаемый способ запуска.** Если появится
   потребность в контейнеризации boxframe — отдельная задача:
   Dockerfile будет строиться от установленного пакета
   (`pip install boxframe` + entry point `boxframe`), а не от
   исходников репозитория.
2. **Страница PyPI обновится только при следующем релизе.** README
   без Docker попадёт в публикацию при следующем теге `v*`.
