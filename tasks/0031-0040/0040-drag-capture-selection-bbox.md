# Суть проблемы

Правило захвата элемента для перетаскивания было привязано строго к
блоку под курсором: `onCanvasMouseDown` в `editor.js` делал hit-test по
`this.blocks` (отсортированным по `order` desc) и начинал drag только
того блока, чья абсолютная область содержала курсор.

Из-за этого активное выделение (один блок или группа) не «захватывалось»
рамкой:

- чтобы сдвинуть группу, приходилось нажимать именно на один из блоков
  группы — в «пробелах» между блоками (пустой канвас внутри bounding box
  выделения) курсор попадал на пустоту и начинался marquee, а не drag
  группы;
- на невыделенном блоке, попавшем внутрь рамки выделения, начинался drag
  этого одиночного блока, а не всей группы;
- обычный клик внутри рамки выделения (без движения) схлопывал
  мульти-выделение в один блок — выделение сбивалось.

# Задача

Изменить правило захвата элемента для перетаскивания:

1. Если есть активное выделение (один блок или группа) и мышь
   зажимается **внутри его bounding box** — перетаскивается всё
   выделение (группа), даже если курсор на пустом канвасе или на
   невыделенном блоке внутри рамки.
2. Во всех остальных случаях выбор элемента происходит по существующим
   правилам (hit-test блока под курсором, marquee по пустому канвасу,
   Shift/Ctrl+click — toggle).
3. Клик внутри рамки выделения без движения не сбивает текущее
   выделение.

# Исследование

1. **Захват идёт в `onCanvasMouseDown`.** До hit-test уже отсекаются
   клики по `block-edit-overlay`, `block-selection` (рамка + handle),
   `block-props`. Новое правило вставляется сразу после этих отсечек и
   до hit-test по блокам — оно имеет приоритет над одиночным блоком,
   потому что рамка выделения зрительно «поверх» блоков.
2. **Бbox — абсолютные координаты.** Дети несут относительные координаты,
   поэтому bounding box считается по `_absoluteRect` каждого выбранного
   блока (union). Для одиночного блока bbox = его собственный rect.
3. **Якорь drag.** Для одиночного блока якорь — его абсолютный rect
   (`dragGroupAnchor = _absoluteRect(block)`), дельта = `gx - anchor.x`.
   Для захвата рамкой якорь — левый верхний угол bbox; дельта группы
   остаётся равной смещению мыши в сетке (якорь задаёт только точку
   отсчёта, формула дельты не меняется).
4. **Модификаторы исключены.** Shift/Ctrl+click — это toggle выделения,
   не drag. Если зажат модификатор, новое правило не срабатывает и
   сценарий идёт по старым путям (toggle / marquee).
5. **Клик без движения.** В режиме `pending` без превышения порога
   (3px) это клик. Раньше любой клик по блоку делал `selectBlock`
   (схлопывал группу). Для `dragSelection` клик внутри рамки ничего не
   меняет — выделение сохраняется.
6. **Resize handle не затронут.** `.sel-resize` имеет
   `pointer-events: auto` и перехватывает mousedown до канваса
   (`onSelectionResizeMouseDown`), поэтому resize рамки работает как
   раньше.

# Замечания

1. **Приоритет правила.** Захват рамкой срабатывает раньше hit-test по
   блокам: если курсор внутри bbox выделения, одиночный блок под
   курсором (даже невыделенный) не захватывается — двигается группа.
   Это осознанное поведение: рамка выделения зрительно «поверх» блоков и
   задаёт область управления группой.
2. **Одиночное выделение.** Для одного блока bbox = его rect, поэтому
   нажатие на сам блок ведёт в `dragSelection` (а не в hit-test).
   Результат эквивалентен прежнему одиночному drag: якорь — rect блока,
   дельта — смещение мыши. Поведение одиночного блока не изменилось.
3. **Resize-область рамки.** `.sel-resize` (handle в углу рамки)
   перехватывает mousedown до канваса — resize группы работает как
   раньше и не конфликтует с новым правилом захвата.
4. **Static-режим покрыт тем же кодом** — `editor.js` общий для web- и
   static-режимов, `LocalStorageStore` поддерживает `batchBlocks`;
   e2e-тесты для static-режима на это правило не добавлялись (web-режим
   проверяет общий код).
5. **Кандидат на будущую задачу.** Можно добавить визуальную подсказку
   (курсор `move` / подсветка рамки) при наведении внутри bbox
   выделения, чтобы пользователь заранее видел, что будет двигаться
   группа, а не одиночный блок.
