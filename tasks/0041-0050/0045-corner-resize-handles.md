# Суть проблемы

Когда элемент (или группа) был выделен, рамка выделения
(`.block-selection`) имела **одну** ручку ресайза — в правом нижнем
углу (`.sel-resize`). Размер можно было менять только «растягиванием»
вправо-вниз: `x`/`y` не менялись, росли только `width`/`height`.

Это не покрывало обычные сценарии:

1. **Сжать блок** — уменьшить ширину/высоту с любой стороны.
2. **Переместить край** — сдвинуть левый/верхний край, сохранив
   противоположный (например, «подтянуть» левый край блока к
   соседу).
3. **Согласовать группу** — при выделении нескольких блоков bbox
   можно было только расширять, а не сжимать и не сдвигать.

Отсутствие угловых ручек — стандартное ограничение UX: в Figma,
Illustrator и аналогах выделение всегда показывает ручки на всех
углах, и за любую можно тянуть.

# Задача

Пока элемент (или группа) выделен, отображать горячие точки на всех
четырёх углах рамки выделения и позволять менять размер мышью за
любой из них: перетаскиваемый угол следует за курсором,
противоположный остаётся на месте. Для группы — каждый блок получает
дельту bbox (позиция + размер).

# Исследование

1. **Resize-путь.** `onSelectionResizeMouseDown` → `_startResizeDrag`
   кладёт блок(и) в `dragBlock`/`resizeOriginal`, resize-ветка
   `onCanvasMouseMove` считает превью, `_commitBlockResize` пишет в
   store. Для группы уже была логика «bbox + дельта на каждый блок»
   (только `width`/`height`), для одиночного — только `width`/`height`.
   Значит, добавление угла = расширение этой же цепочки, а не новый
   механизм.
2. **Координаты.** Блоки в `this.blocks` — плоский список, дети несут
   координаты, **относительные** родителю. Все геометрические вычисления
   resize идут в абсолютных (canvas) координатах через
   `_absoluteRect`; при commit одиночного ребёнка абсолютная позиция
   обратно переводится в относительную через `_absToRel`. Это же
   правило, что и в move (0038/0040).
3. **Минимальные размеры.** 2×2; `hline`/`vline` — всегда 1 клетка
   толщиной; `button` поддерживает `h=1`. Эти clamp'ы уже были в
   resize-ветке — при сжатии от угла нужно сохранить их и **зафиксировать
   неподвижный угол** (двигавшийся край останавливается на минимальном
   расстоянии).
4. **Граница холста.** Блоки могут выходить за границы layout, но не
   за начало холста (0,0) — это же ограничение, что и в move/nudge.
   При сжатии от левого/верхнего угла двигающийся край останавливается
   на 0, неподвижный остаётся.
5. **DOM-ручки.** Ручки — статические div'ы в `.block-selection`
   (Alpine `x-show`), не пересоздаются при каждом рендере, поэтому
   `data-corner` + один `@mousedown`-обработчик на каждую достаточно;
   привязывать их заново (как hover-ручки в `_bindResizeHandles`) не
   нужно.

# Выполнение задачи

Изменены 6 файлов. Рендереры и формат псевдографики не тронуты.

**`boxframe/static/js/editor.js`:**

- State: `resizeCorner` (`'nw'|'ne'|'sw'|'se'`, по умолчанию `'se'`),
  `resizeStartX/Y` (стартовая позиция bbox/блока), `resizeOriginal`
  теперь хранит `x/y` в дополнение к `width/height`.
- `onSelectionResizeMouseDown` — читает угол из `data-corner` ручки
  (`e.target.closest('.sel-resize').dataset.corner`), передаёт в
  `_startResizeDrag(block, e, corner)`.
- `_startResizeDrag` — запоминает `resizeCorner` и стартовую позицию
  (для группы — minX/minY bbox, для одиночного — абсолютный rect).
- Resize-ветка `onCanvasMouseMove` — расчёт прямоугольника от угла:
  snap смещения на полклетки, `switch (resizeCorner)` двигает нужный
  край; затем clamp минимального размера (группа — bbox, одиночный —
  по типу блока) и границы холста (0,0); для `nw`/`sw` (левый край
  подвижный) и `nw`/`ne` (верхний край подвижный) неподвижный угол
  пересчитывается из финального размера. Превью двигается по позиции
  **и** размеру (`_showPreview(newX, newY)`).
- `_commitBlockResize`:
  - одиночный — `updateBlock({ x, y, width, height })`; ребёнок
    конвертируется в относительные координаты через `_absToRel`;
  - группа — `batchBlocks` с дельтой bbox (`dX/dY/dW/dH`) на каждый
    блок, с теми же clamp'ами по типу; один batch = один шаг undo.
- `_clearDragState` — сброс `resizeCorner` в `'se'`.

**`boxframe/static/css/editor.css`:**

# Замечания

1. **Поведение стало полнее, не противоречит старому.** Drag за `se`
   ведёт себя как раньше (только рост) — старые тесты и сценарии
   не сломаны; остальные три угла — новое.
2. **Групповой resize — дельта bbox, а не «растянуть каждый до края».**
   Каждый блок получает одинаковый сдвиг и прирост (с clamp'ами по
   своему типу), поэтому внутренняя геометрия группы сохраняется —
   блоки не «схлопываются» и не «разъезжаются». Это осознанный выбор,
   согласующийся с move-группы (0038/0040).
3. **Неподвижный угол — инвариант.** При clamp'е минимального размера и
   у границы холста (0,0) двигающийся край останавливается, а
   противоположный угол не сдвигается — это ключевое отличие от
   «растягивания» и причина пересчёта `newX/newY` из финального размера
   для углов `nw`/`sw`/`ne`.
4. **Координаты ребёнка.** Как и в move, при resize одиночного ребёнка
   абсолютная позиция обратно конвертируется в относительную
   (`_absToRel`) — родительский контейнер не меняется, блок остаётся
   внутри него.
5. **Undo/redo.** Одиночный resize — один `updateBlock`, групповой —
   один `batchBlocks`; оба — по одному шагу в истории. Coalescing не
   нужен (resize завершается одним commit'ом на mouseup).
6. **Hover-ручки (`.resize-handle` в блоках) не тронуты** — они
   продолжают работать независимо; на выделенном блоке показывается
   рамка с 4 угловыми ручками, hover-ручка подавлена (как и раньше).
