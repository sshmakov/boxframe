# Суть проблемы

При изменении размера выделенного элемента мышью за любой угол, кроме
правого нижнего, иногда сдвигалась сторона, **не** прилегающая к
перетаскиваемому углу. К примеру, после ресайза за левый нижний угол
мог уехать верхний правый угол, который должен был остаться на месте.

Это ломает ключевой инвариант углового ресайза (0045): «перетаскиваемый
угол следует за курсором, противоположный остаётся на месте». Превью во
время drag было корректным — сдвиг появлялся только после отпускания
мыши, когда результат записывался в store.

# Задача

Исправить округление в `_commitBlockResize()` так, чтобы зафиксированный
угол оставался на месте для всех четырёх углов (`nw`/`ne`/`sw`/`se`), не
меняя поведение `se` и не трогая логику клампинга (минимальный размер,
граница холста 0,0).

# Исследование

1. **Snap на полклетки.** Во время drag смещение курсора снапится к
   полклетке — `onCanvasMouseMove`:
   `snapDx = Math.round((dx / charWidth) * 2) / 2`. Поэтому
   `resizePreviewX`/`resizePreviewW` (и `Y`/`H`) часто имеют дробную
   часть `.5`.
2. **Независимое округление в коммите.** `_commitBlockResize()`
   округлял позицию и размер **отдельно**:
   `absX = Math.round(resizePreviewX)`,
   `absW = Math.round(resizePreviewW)`.
3. **Зафиксированный угол — это сумма.** Для углов `nw`/`ne`/`sw`
   неподвижный угол задаётся суммой координаты и размера (например,
   правый край = `newX + newW`). Но `round(X) + round(W) ≠ round(X + W)`:
   когда оба значения стоят на `.5`, независимое округление сдвигает эту
   сумму на ±1 клетку.
4. **Почему «иногда».** Сдвиг появляется только когда мышь отпущена на
   полклетке (нечётное число × 0.5). Целые смещения сумму не ломают —
   отсюда непостоянное воспроизведение.
5. **Почему не `se`.** Для правого нижнего угла зафиксирован левый
   верхний `(startX, startY)` — исходные целые координаты, которые не
   участвуют в сумме и не «плывут». Для остальных трёх углов
   зафиксированный угол — именно сумма координаты и размера, и она
   смещается.

**Пример** (`sw`, `startX=5`, `startW=10`, drag вправо на полклетки,
`snapDx=+0.5`): превью `newX=5.5`, `newW=9.5` → правый край
`5.5 + 9.5 = 15` (точно, угол на месте); коммит
`absX=round(5.5)=6`, `absW=round(9.5)=10` → правый край `6 + 10 = 16` —
сдвинулся на +1.

# Выполнение задачи

Изменён 1 файл: `boxframe/static/js/editor.js`
(`_commitBlockResize`). Рендереры, формат псевдографики и CSS не тронуты.

Вместо независимого округления `absX`/`absY`/`absW`/`absH` теперь:

- фиксированные грани берутся как есть (целые, из `resizeStartX/Y/W/H`);
- округляется только **движущаяся** грань:
  - `nw`/`sw` — левый край подвижный: `absX = round(resizePreviewX)`,
    `absW = (startX + startW) - absX`;
  - `ne`/`se` — правый край подвижный: `absX = startX`,
    `absW = round(resizePreviewX + resizePreviewW) - absX`;
  - по вертикали аналогично для `nw`/`ne` (верхний) и `sw`/`se`
    (нижний).

Сумма `x + w` (и `y + h`) теперь всегда совпадает с исходной целой
координатой зафиксированного угла. Поведение `se` не изменилось (левый
верхний угол и так был целым); клампинг минимального размера и границы
холста работает на превью до коммита — как и раньше.

**`tests/js/test_editor.js`** — 6 регрессионных тестов (drag/resize в
`editor.js` уже частично покрывался с 0045, но все commit-тесты
использовали целые смещения — полуклеточный случай не был покрыт):

- превью полуклеточного drag (`sw`, 0.5 вправо/вниз) — фиксированные

# Замечания

1. **Регрессия покрыта unit-тестами** (`tests/js/test_editor.js`,
   секция «Commit rounding (0047)») — повторная ручная проверка не
   требуется. Паттерн тестов (`cornerResize` + `stubStore`) работает
   без DOM: resize-ветка `onCanvasMouseMove` и `_commitBlockResize`
   самодостаточны — новые drag/resize-тесты можно писать так же.
2. **Инвариант: фиксированный угол — целая сумма.** Любое будущее
   изменение commit-логики resize должно сохранять свойство
   `round` только движущейся грани; нельзя возвращаться к независимому
   округлению `x` и `width` (и `y` и `height`).
3. **Snap на полклетки — источник дробных превью.** Если в будущем
   snap уберут или сделают целочисленным, дробные превью исчезнут и
   баг не воспроизведётся — но текущий фикс корректен и в этом случае
   (округление целого = то же целое).
4. **Групповой resize** использует те же `absX/absY/absW/absH` как дельту
   bbox — фикс автоматически распространяется и на него.
