# Суть проблемы

По клику (или перетаскиванию) в редакторе не всегда выбирался самый
верхний элемент под курсором. Hit-test (`onCanvasMouseDown` в
`boxframe/static/js/editor.js`) был **плоским**: по отсортированному
по `order` (убыванию) плоскому списку `this.blocks` брался первый блок,
абсолютная область которого содержала точку.

Рендерер же (Python и JS, ASCII и HTML-оверлей) рисует **иерархически**:
root-блоки — по возрастанию `order`, а ребёнок — внутри своего
контейнера (после контента родителя, с клиппингом по внутренней
области). Из этого следовало три расхождения:

1. **Ребёнок vs контейнер.** Ребёнок всегда рисуется поверх своего
   контейнера, но при `order(контейнера) > order(ребёнка)` клик по
   ребёнку выбирал контейнер.
2. **Ребёнок высокого контейнера vs средний корень.** Ребёнок рисуется
   в слое контейнера — поверх всех корней с `order` ниже
   `order(контейнера)`. При `order(ребёнка) < order(корня) <
   order(контейнера)` визуально верхним был ребёнок, а выбирался корень.
3. **Tie-break при равном `order` был зеркальным.** Рендерер: стабильная
   сортировка по возрастанию → при равенстве сверху тот, кто **позже**
   в документе. Hit-test: стабильная сортировка по убыванию + `find` →
   брал того, кто **раньше** в документе, т.е. нижний. Равные `order`
   возможны в static-режиме (нормализации дубликатов нет) и временно в
   web-режиме (после `updateBlock`, до перезагрузки).

Дополнительно:

4. **Устаревший порядок после смены `order`.** `updateSelectedBlock`
   (поле Order в панели свойств) обновлял блок, но не пересортировывал
   `this.blocks` — следующий клик по пересекающимся блокам решал
   «верхность» по старому порядку.
5. **Bbox-захват выделения перекрывал topmost.** По поведению из 0040
   нажатие внутри bounding box выделения тащило всю группу «даже когда
   курсор на невыделенном блоке внутри box» — т.е. верхний под курсором
   блок игнорировался.

# Задача

По клику (или перетаскиванию) из элементов под курсором должен
выбираться самый верхний элемент — в точности совпадающий с порядком
отрисовки рендерера (иерархия + `order` + клиппинг + tie-break по
документному порядку).

# Исследование

1. **Клик и drag — один путь.** `onCanvasMouseDown` находит блок под
   курсором и кладёт его в `pendingBlock`; без движения мыши (клик) —
   `selectBlock`, с движением > 3px — move-drag. Значит, фикс hit-test'а
   покрывает и клик, и drag сразу.
2. **Порядок отрисовки рендерера** (`renderer.py` / `core/renderer.js`,
   совпадают по parity):
   - root-блоки — стабильная сортировка по возрастанию `order`;
   - ребёнок рисуется внутри контейнера: после рамки/контента родителя,
     до следующего root-блока; т.е. ребёнок **всегда** поверх своего
     предка и поверх всех root-блоков с `order` ниже `order(предка)`;
   - дети рисуются только у bordered-блоков (border_style != none,
     >= 2x2); у `button`/`hline`/`vline` — никогда;
   - ребёнок клипится по внутренней области контейнера (рамка не
     перерисовывается) — вылезшая за рамку часть невидима.
3. **HTML-оверлей** (CSS `z-index: 10 + order`, дети вложенными div'ами
   с `overflow:hidden`) даёт ту же «верхность», что и ASCII — hit-test
   приводится к ней, рендереры менять не нужно.
4. **Tie-break.** И Python `sorted()`, и `Array.prototype.sort`
   стабильны: при равном `order` сверху тот, кто позже в документе.
   Сервер нормализует дубликаты `order` (`_normalize_block_orders`), но
   static-режим (LocalStorageStore) нормализации не имеет — равные
   `order` в данных возможны; нужен детерминированный клиентский
   tie-break.
5. **Bbox-захват (0040)** был осознанным решением «тащить группу из
   пустого места внутри bbox», но формулировка «даже на невыделенном
   блоке внутри box» противоречит правилу «верхний под курсором
   выигрывает» (как в Figma): клик по верхнему невыделенному блоку
   должен его выбрать, а не тащить чужую группу.

# Выполнение задачи

Изменены 2 файла: `boxframe/static/js/editor.js` (код) и
`tests/js/test_editor.js` (тесты). Рендереры не тронуты.

**`boxframe/static/js/editor.js`:**

- `_blockAt(x, y)` — иерархический hit-test: среди root-блоков под
  точкой берётся максимум по `(order, _seq)`, затем спуск внутрь, пока
  точка во внутренней области (padding 1 клетка) и покрывает
  topmost-ребёнок. Возвращает верхний **видимый** блок или null.
- `_childrenRendered(b)` — правило «у кого рендерер рисует детей»
  (bordered >= 2x2, не button/hline/vline) — учёт клиппинга и
  borderless-контейнеров.
- `_seq` — монотонный штамп документного порядка: ставится в
  `_flattenBlocks` (pre-order: родители до детей — тот же порядок, что
  в вложенном ответе API и экспорте), `addBlock`, `duplicateBlock`,
  `_applyBatchResult` (created). Клиентский, не персистится; при
  перезагрузке проставляется заново.
- `_reorderBlocks()` — сортировка `(order desc, _seq desc)`: порядок
  списка совпадает с «верхностью» рендерера (сайдбар + плоские
  обходы).
- `onCanvasMouseDown` — topmost через `_blockAt`; bbox-захват группы —
  только если под курсором пусто или выделенный блок; на невыделенном
  topmost блоке он выбирается/тащится.
- `onCanvasDblClick` — тот же `_blockAt` (был плоский `find`).
- `updateSelectedBlock` (single) — `_reorderBlocks()` после
  `updateBlock` (смена `order` в панели свойств).
- `_applyBatchResult` — `_seq` для created + `_reorderBlocks()`
  (batch может менять `order`).

**`tests/js/test_editor.js`** — 12 тестов:

- `_blockAt`: верхний по `order`; half-open границы (правая/нижняя
  рамка — вне); tie-break по документному порядку; ребёнок поверх
  контейнера (даже с меньшим `order`), на рамке контейнера —
  контейнер; ребёнок высокого контейнера против среднего корня;
  borderless-контейнер не рисует детей; button не рисует детей;
  спуск через вложенные уровни (внук); клип — ребёнок, вылезший за
  рамку, в обрезанной зоне не выбирается;
- `updateSelectedBlock`: смена `order` пересортировывает список;
- mousedown: невыделенный topmost выигрывает у bbox выделения; пустой
  канвас внутри bbox — группа; нажатие на выделенный блок — группа.

# Замечания

1. **Поведение изменилось в двух местах (осознанно):**
   - клик по ребёнку внутри контейнера теперь всегда выбирает ребёнка
     (раньше — контейнер, если у того был бóльший `order`);
   - нажатие на невыделенный верхний блок внутри bbox выделения
     выбирает этот блок, а не тащит группу (0040 сужен: группа
     тащится из пустого места внутри bbox и с выделенных блоков).
2. **`_seq` — клиентский штамп, не часть данных.** Не персистится и не
   уходит в API; при перезагрузке проставляется из документного
   порядка, поэтому tie-break совпадает со стабильной сортировкой
   рендерера и в web-, и в static-режиме.
3. **Рендереры не менялись** — hit-test приведён к их порядку
   отрисовки, а не наоборот; формат псевдографики не тронут.
4. **Marquee не менялся** — полное вхождение в прямоугольник, z-порядок
   для него не имеет смысла.
5. **Hover-resize-ручки** привязаны к DOM-оверлеям (CSS z-index) и
   уже показывались у верхнего блока — с новым hit-test'ом поведение
   клика согласовано.
6. В `_bindResizeHandles` остался отладочный `console.log`
   (`[editor] Found N block previews`) — предсуществующий, не тронут;
   кандидат на удаление в отдельной задаче.
