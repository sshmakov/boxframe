# Суть проблемы

После импорта JSON (кнопка Import или drag-and-drop, задача 0055)
редактор перерисовывается, но выделение не меняется: импортированные
блоки не выделены. Чтобы переместить/отредактировать импортированный
набор, пользователь должен сам выделить его рамкой (marquee) или
кликать по каждому блоку. Особенно неудобно при импорте в непустой
макет (режим add): импортированные блоки лежат поверх существующих,
и выделить именно их — отдельная ручная операция.

# Задача

После успешного импорта все импортированные блоки становятся
выделением — в любом из трёх сценариев `_applyImport`:

- импорт в пустой редактор (replace);
- add в непустой макет (OK в confirm) — выделяются только
  импортированные блоки, существующие — нет;
- replace непустого макета (Cancel в confirm).

Выделение — обычное многократное (`selectedIds`): можно сразу
перетаскивать группу, двигать стрелками, дублировать (Ctrl+D),
удалять, открывать панель свойств (первый блок — primary).

# Исследование

- `_applyImport` (editor.js) в трёх ветках строит новый state через
  `prepareImport(...)` (core/import.js) — результат содержит **новые**
  client-ids (idMap внутри `prepareImport`), поэтому именно его список
  нужно запомнить: ids из файла (`imp-1`, `imp-2`) в редактор не
  попадают.
- Выделение в редакторе — `selectedIds: []` (первый id — primary для
  панели свойств). Конвенция «операция создаёт блоки → они становятся
  выделением» уже есть у `duplicateBlock` (`this.selectedIds =
  copies.map(b => b.id)` после `replaceState`).
- Подсветка canvas-оверлеев — не реактивная: `_markSelectedPreviews()`
  вызывается из `refreshRender()` в `$nextTick`. `selectedIds` надо
  выставить **до** `_syncStateFromStore()` (который внутри вызывает
  `refreshRender()`), чтобы подсветка применилась к новому выделению.
  Фильтр «отбросить несуществующие id» внутри `_syncStateFromStore`
  импортированные id не тронет — они уже есть в состоянии.
- Список элементов в сайдбаре — реактивный (`:class` по
  `selectedIds.includes(block.id)`), обновится сам.
- Импорт идёт через `store.replaceState` — одна запись undo/redo;
  undo после импорта вернёт прежнее состояние, а `selectedIds`
  отфильтруется `_syncStateFromStore` (поведание как у любого другого
  undo — без изменений).

# Замечания

1. Выделяется **весь** импортированный набор, включая вложенные
   (дети контейнеров из файла) — `prepareImport` возвращает плоский
   список всех блоков, и это совпадает с ожиданием «переместить
   импортированный макет целиком».
2. Primary (первый в `selectedIds`) — первый блок файла в
   документном порядке (обычно внешний контейнер); панель свойств
   открывается к нему.
3. Undo после импорта снимает выделение «естественно»:
   `_syncStateFromStore` отбрасывает id, которых нет в восстановленном
   состоянии (в режиме add — импортированные исчезают, выделение
   пустое; в режиме replace — пусто).
4. Drag-and-drop импорт (0055) проходит через тот же `_applyImport` —
   выделение работает и для него, отдельной логики нет.
