# Суть проблемы

Inline-редактирование текста (double-click на блок → textarea) позиционирует поле строго по геометрии блока. Для маленьких блоков (`button` 8×1, `text` 5×1) поле получается ~60×16px — практически невозможно набирать текст.

# Задача

Расширить пространство редактирования: textarea должна иметь комфортный минимальный размер, оставаясь привязанной к позиции блока.

# Исследование

Текущая реализация: `editOverlayStyle` вычисляет `left`, `top`, `width`, `height` из геометрии блока (`width * charWidth`, `height * charHeight`). Для блока `button` 8×1 при `charWidth≈7.2px` — это ~58×14px.

Рассмотрены варианты:
1. CSS `min-width/min-height` — просто, но нет clamp к краю canvas
2. Auto-grow по содержимому — сложно, непредсказуемо
3. Expand-on-focus (фиксированный минимум) — детерминировано, просто ✓
4. Floating-панель рядом с блоком — больше кода
5. Bottom/side drawer — занимает место
6. Гибрид с resizable handle — минимальное изменение, но UX хуже

Выбран вариант 3: фиксированный минимум + clamp.

# Выполнение задачи

Изменён `editOverlayStyle` в `boxframe/static/js/editor.js`:

- **Минимум:** `MIN_W = 320`, `MIN_H = 96` (~44 символа × 6 строк при 11px моноширинном)
- **Логика:** `max(блок, минимум)` по каждой оси
- **Clamp:** если расширенный overlay вылезает за правый/нижний край layout (`layoutWidth * charWidth` / `layoutHeight * charHeight`), поле сдвигается влево/вверх; левый/верхний край не уходит ниже padding (16px)
- Оба редактора (web и static) используют один `editor.js` — изменение одно

Результат: `button` 8×1 → поле 320×96px; `box` 60×20 → поле остаётся по размеру блока.

Не выполнено: визуальная привязка к блоку (выноска/линия от textarea к блоку) — не требуется, позиция textarea начинается у блока и выступает в свободную сторону.

# Замечания

- Значения `MIN_W=320` / `MIN_H=96` подобраны эвристически; при изменении `font-size` textarea (сейчас 11px в `editor.css`) стоит пересчитать
- Для layout без заданных размеров (`layoutWidth`/`layoutHeight` null — static-режим без layout) clamp не применяется; в статическом редакторе layout обычно задан
- В будущем, если нужно editing для очень длинного текста, можно добавить `overflow-y: auto` и/или динамический рост по содержимому поверх текущего минимума
