# Суть проблемы

Когда один приклеенный блок (`header`/`footer`/`sidebar`) усекается по
углу **с двух противоположных сторон**, два усечения не компонуются.
`_plan_attached` (`renderer.py`) / `planAttached` (`renderer.js`) при
усечении края якорил размер на **внутренний край `box`**
(`(py+1)−…` / `(px+1)−…` / `(py+ph−1)−…` / `(px+pw−1)−…`), игнорируя,
что противоположный край уже сдвинут предыдущим усечением.

Проявление: в `box` с `header`+`footer`+`sidebar` (или `header`/`footer`
между двумя `sidebar`) линия подчинённого **перерастает** линию chrome в
соседний блок — например вертикальная линия `sidebar` видна **внутри**
`footer` (`layout_4.json`, верхний левый `box`).

# Задача

Сделать угловые усечения композируемыми и независимыми от порядка пар:
каждое усечение сохраняет **текущий** противоположный край эффективного
прямоугольника, а не внутреннюю границу `box`. Правка в обоих рендерах,
тесты py/js/parity на трёхстороннюю и двухсайдбаровую композиции.

# План работ

- [x] `renderer.py` `_plan_attached`: низ/правое усечение якорятся на
      текущем `eff`-крае; верх/левое сохраняют текущий дальний край.
- [x] `renderer.js` `planAttached` — тот же порт (parity побайтово).
- [x] Тесты: `test_renderer.py` (+2), `test_renderer.js` (+2),
      `test_js_renderer_parity.py` (+1 `test_parity_attached_corner_composition`).

# Детали реализации

Ветка `dom == "H"` (усечение `sidebar` горизонталями):
```
# верх (header): сохраняем текущий НИЗ
bottom = vr.eff[1] + vr.eff[3] - 1
vr.eff[1] = lr + 1
vr.eff[3] = bottom - (lr + 1) + 1
# низ (footer): якорь на теку ВЕРХУ (eff[1]), не (py+1)
vr.eff[3] = (lr - 1) - vr.eff[1] + 1
```
Ветка `dom == "V"` (усечение горизонтали `sidebar`-ами):
```
# лево: сохраняем текущий ПРАВОЙ край
right = hr.eff[0] + hr.eff[2] - 1
hr.eff[0] = col + 1
hr.eff[2] = right - (col + 1) + 1
# право: якорь на теку ЛЕВОМ краю (eff[0]), не (px+1)
hr.eff[2] = (col - 1) - hr.eff[0] + 1
```
Порядок пар (`recs` = порядок детей) больше не влияет на итог: каждое
усечение читает уже изменённый противоположный край. `meeting_ops`/
`border_ops` и гейты `trimTop/Bottom/Left/Right` не меняются — при
двустороннем усечении оба конца дают `trim*=True`, border-junction на
обоих концах не emission-ится.

# Замечания

- **Обратная совместимость:** меняет вывод существующих макетов с такой
      композицией (линия больше не лезет в соседний chrome-блок). Фикс
      багованный вывод → корректный; согласовано с пользователем (2026-11-10).
- Не связано с переходом на эффективную геометрию доминанты (e459d5f):
      для затронутых макетов `dom` был тем же и по сохранённым координатам.
