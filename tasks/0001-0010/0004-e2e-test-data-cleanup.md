# Е2Е-тесты накапливают данные в БД между запусками

## Суть проблемы

E2E-тесты (Playwright) работают с живым сервером (`http://127.0.0.1:8000`) и создают проекты/лейауты через UI.
Текущий `reset_page_state` сбрасывает только UI-состояние (навигация + Escape), но **данные БД накапливаются** между тестами.

Это означает:
- При повторных запусках E2E-тестов в БД остаются «хвосты» от предыдущих прогонов
- Невозможно отличить тестовые данные от реальных
- Тесты, полагающиеся на подсчёт элементов (например `test_delete_button_exists`), работают, но состояние БД «грязное»

## Задача

Обеспечить автоматическую очистку тестовых данных между E2E-тестами и маркировать их для отличия от реальных.

## Замечания

### Обнаруженный баг
При создании лейаута через UI сервер возвращал 500: `UndefinedError: 'blocks' is undefined`.
Роут `page_editor` не передавал `blocks` в шаблон `editor.html`, хотя шаблон использовал `{{ blocks.length }}`.

### Архитектурные выводы
1. **E2E-тесты требуют запущенного сервера** — fixture `cleanup_db` корректно обрабатывает ситуацию, когда сервер не запущен (try/except)
2. **Префикс в имени проекта** — простое и эффективное решение, не требует миграции БД
3. **API-эндпоинт для очистки** — работает через HTTP, не требует доступа к сессии БД из тестов
4. **Порядок удаления** — blocks → layouts → projects (из-за FK constraints), реализовано через SQL DELETE с WHERE IN
