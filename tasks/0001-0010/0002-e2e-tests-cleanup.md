# Суть проблемы

E2E-тесты на Playwright использовали живой сервер и взаимодействовали с UI напрямую.
При открытии форм (например, "+ New Project" через Alpine.js) состояние страницы
сохранялось между тестами — следующий тест мог видеть открытую форму, что приводило
к нестабильным результатам или ложным срабатываниям.

# Задача

Добавить автоматический сброс состояния страницы между e2e-тестами, чтобы каждый тест
начинал работу с чистого листа.

- [x] Создать `conftest.py` в `tests/e2e/` с автоиспользуемым fixture
- [x] Реализовать сброс UI-состояния: навигация на `/`, нажатие `Escape`, ожидание анимаций
- [x] Запустить тесты и убедиться, что все проходят

# Исследование

1. **Структура тестов:** 6 e2e-тестов в двух файлах (`test_projects.py`, `test_editor.py`),
   все используют `Page` fixture из Playwright.
2. **UI-фреймворк:** Приложение использует HTMX + Alpine.js. Alpine.js хранит состояние
   форм в переменных (`x-data`), которые не сбрасываются при навигации по якорям.
3. **Проблема:** Тест `test_new_project_button` кликает "+ New Project", открывая форму.
   Без сброса следующий тест видит форму в неожиданном состоянии.
4. **Решение:** Автоиспользуемый fixture `reset_page_state` с `autouse=True` — срабатывает
   после каждого теста, не требуя явного вызова.

# Выполнение задачи

Создан файл `tests/e2e/conftest.py` с fixture `reset_page_state`:

- **Навигация на `/`** — сбрасывает весь DOM и Alpine.js состояние
- **`page.keyboard.press("Escape")`** — закрывает любые открытые dropdown-формы
- **`page.wait_for_timeout(200)`** — даёт время settle-анимациям завершиться

Все 6 тестов прошли успешно за 5.71 сек (было 3.87 сек — добавление cleanup добавляет
~200мс за тест, что приемлемо).

# Замечания

- Автоиспользуемый fixture — правильный подход для e2e-тестов: не требует явного
  включения, работает для всех тестов в директории автоматически.
- `wait_for_timeout` — неидеален с точки зрения best practices (лучше использовать
  `expect().to_be_visible()` или `page.wait_for_load_state()`), но для простого
  settle-ожидания приемлем.
- В будущем можно добавить fixture для очистки БД между тестами, если e2e-тесты
   начнут создавать/модифицировать данные.
- Для тестов, которым нужно специальное начальное состояние, можно использовать
  `request_fixture` override или параметризацию.
