# Суть проблемы

В HTML-превью редактора блоки со стилем рамки `none` отображались без
рамки: `_border_html()` в `renderer.py` возвращал пустую строку, а в CSS
не было правила `.block-border--none`. На канве оставался только текст
контента (или вообще ничего, если контент пуст) — блок было трудно
заметить, выделить и изменить размер. Для `hline`/`vline` со стилем
`none` превью не содержало элемента `block-line` вовсе.

# Задача

Показывать полупрозрачную рамку в HTML-превью редактора даже для
элементов, у которых стиль линии `none` — чтобы границы блока оставались
видны, выделяемы и resize-абельны, хотя в псевдографике рамка не
рисуется.

# Исследование

1. **Рамка превью строится на сервере** — `RenderBlock._border_html()`
   генерирует `<div class="block-border block-border--{style}">`, а стили
   задаются CSS-классами в `editor.html`. Для `none` метод возвращал `""`
   — элемент-рамка не создавался вовсе.
2. **CSS покрывал только 4 стиля** — правила были для `solid`, `dashed`,
   `dotted`, `double`; правила `--none` не существовало, так что даже
   добавив класс, рамка бы не отрисовалась.
3. **Был тест, закрепляющий старое поведение** —
   `test_render_html_preview_line_none` утверждал
   `"block-line" not in html`; его пришлось переписать под новое
   поведение.
4. **ASCII-рендер не затронут** — отрисовка псевдографики идёт отдельным
   путём (`_render_block()`), где `none` по-прежнему не рисует ничего;
   менять формат вывода не нужно.

# Выполнение задачи

Изменено 3 файла:

**`boxframe/services/renderer.py`**:
- `_border_html()` — убран ранний `return ""` для `none`; в `border_map`
  добавлена запись `"none": "none"`. Теперь для любого блока генерируется
  `block-border--none`, для `hline`/`vline` —
  `block-line--{h|v} block-line--none`.

  блока рамки нет.

  `block-line--h block-line--none`.
- Новый `test_render_html_preview_border_none` — обычный блок с `none`
  получает `block-border--none`.

# Замечания

1. **Семантика `none` в превью — «блок есть, рамки в выводе нет»** —
   бледный пунктир не должен путать с реальным `dashed` (он — тот же
   цвет, но прозрачность 0.5). Если в будущем появятся новые стили,
   правила CSS и `border_map` в `_border_html()` нужно дополнять
   синхронно (в мапе есть fallback на `solid`, который маскирует
   неизвестные стили).
2. **ASCII-формат не изменён** — `none` по-прежнему невидим в
   псевдографике; рамка существует только в HTML-превью редактора. Это
   осознанное разделение: превью — инструмент редактирования, а не
   источник данных.
3. **Тесты превью дублируют CSS-классы строкой** —
   `assert 'class="block-border block-border--none"' in html` не
   проверяет, что CSS-правило существует. Если правило удалят, тесты
   продолжат проходить; визуальная проверка остаётся на человеке.
