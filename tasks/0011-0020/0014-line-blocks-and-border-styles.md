# Суть проблемы

В палитре редактора не было компонентов-линий: единственный «разделитель»
(`divider`) рендерился как обычный блок с полной рамкой, а не как одиночная
горизонтальная/вертикальная линия. Нарисовать разделитель в псевдографике
(`─`, `│`, `┄`, `┈`, `═`, `║`) было невозможно — только коробкой.

Второй пробел: `border_style` существовал в модели, API и рендерере (карта
`BORDERS` поддерживала все 4 стиля), но в UI не было способа его выбрать —
каждый блок создавался с `solid` и оставался с ним навсегда. Для AI-readable
формата стиль линии/рамки — часть семантики макета (разделитель, акцент,
граница), и она должна задаваться.

# Задача

1. Добавить новые компоненты — горизонтальную (`hline`) и вертикальную
   (`vline`) линии:
   - `hline` — линия в одну строку, рисуется символом стиля по верхней строке
     блока;
   - `vline` — линия в одну колонку, рисуется символом стиля по левому
     столбцу блока;
   - линии участвуют в drag-and-drop из палитры, перемещении и resize
     (толщина 1 клетка допустима).
2. Добавить возможность выбирать стиль линии и рамки: `solid` (─│),
   `dashed` (┄┆), `dotted` (┈┊), `double` (═║) — для любого блока, включая
   линии; `none` для линии означает невидимость.

# Исследование

1. **Большая часть уже была** — `BORDER_STYLES` в `models/block.py` и карта
   `BORDERS` в `renderer.py` покрывали все 4 стиля для рамок; `border_style`
   уже проходил через `BlockCreate`/`BlockUpdate` и `/api/projects/{id}/info`
   (поле `border_styles`). Не хватало только UI-селектора и типов линий —
   API менять не пришлось.
2. **Палитра генерируется с сервера** — кнопки строятся из `block_types`
   ответа `GET /api/projects/{id}/info`, поэтому добавление в `BLOCK_TYPES`
   автоматически добавило кнопки в палитру (drag-and-drop и клик работают
   без изменений).
3. **Линии ломают допущения рендерера** — `_render_block()` требовал
   `width >= 2 and height >= 2` для рамки; для линии 20×1 рамка не
   рисовалась. Нужен отдельный путь отрисовки (`_draw_line()`), а не
   переиспользование `_draw_border()`.
4. **Resize ограничивал 2×2** — `_commitBlockResize()` и clamp в
   `onCanvasMouseMove()` жёстко ставили минимум 2; для линий ослаблено до 1
   по тонкому измерению.
5. **E2e-тест зависел от числа типов** — `test_palette_buttons_are_draggable`
   хардкодил `to_have_count(12)`; после добавления типов упал (14 кнопок).
   Заменено на `len(BLOCK_TYPES)` — теперь тест не ломается при каждом новом
   типе.

# Выполнение задачи

Изменено 6 файлов + обновлён AGENTS.md:

**`boxframe/models/block.py`**:
- `BLOCK_TYPES` += `hline` (горизонтальная линия, 1 строка), `vline`
  (вертикальная линия, 1 колонка).

**`boxframe/services/renderer.py`**:
- `_render_block()` — ветка для `hline`/`vline`: при `border_style != "none"`
  вызывает `_draw_line()`, контент не рисуется.
- Новый `_draw_line(block, style)` — `hline`: `style["h"]` по строке `y`
  от `x` на `width` символов; `vline`: `style["v"]` по колонке `x` от `y` на
  `height` символов; с clamp'ом к краям сетки.
- `RenderBlock._border_html()` — для линий генерирует
  `<div class="block-line block-line--{h|v} block-line--{style}">` вместо
  рамки; `none` — пусто (как и для блоков).

**`boxframe/templates/pages/editor.html`**:
- CSS `.block-line--h/--v` + 8 комбинаций со стилями (border-top/border-left,
  `double` — 3px, чтобы был виден).
- В списке Elements у каждого блока — `<select class="style-select">` со
  стилями из `borderStyles` (Alpine), `@change → updateBlockStyle()`.

**`boxframe/static/js/editor.js`**:

- `updateBlockStyle(blockId, style)` — `PUT /api/layouts/{id}/blocks/{bid}`

- `_blockDefaults(type)` — единый источник дефолтов: `hline` 20×1, `vline`
  1×5, контент пуст; используется и в `addBlock()`, и в `onCanvasDrop()`.

**`tests/test_renderer.py`** — 10 новых тестов:

# Замечания

1. **`divider` и `hline` дублируют роль** — `divider` рендерится как обычный
   блок с рамкой (особой отрисовки не имеет), `hline` — как линия. В будущем
   стоит либо убрать `divider`, либо дать ему отрисовку линии; пока оба
   типа сосуществуют.
2. **Толщина линии фиксирована: 1 клетка** — `height=1` для `hline` и
   `width=1` для `vline` — инвариант принудительно поддерживается на сервере
   (`LayoutService.create_block`/`update_block`) и в resize-логике редактора
   (фиксированное измерение не меняется при перетаскивании). «Толстая» линия
   не поддерживается — при необходимости это расширение `_draw_line()`.
3. **Селектор стиля — в списке Elements, а не в панели свойств** — выбран
   минимальный путь (один `<select>` на элемент). Если появится больше
   редактируемых свойств (контент, размеры, parent), имеет смысл вынести
   панель свойств выбранного блока — отдельная задача.
4. **E2e-тесты теперь устойчивы к новым типам** — счётчик кнопок палитры
   берётся из `BLOCK_TYPES`; при добавлении типов тесты не требуют правки.
5. **Семантика `none` для линии — невидимость** — последовательно с
   «нет рамки» у блоков; альтернатива (запрет `none` для линий) усложнила бы
   UI без выигрыша.
