# Суть проблемы

Рендерер обрезал текст блока по ширине контентной области: `_draw_content()` в
`services/renderer.py` делал `line = line[:content_w]` для каждой строки. Всё, что
не помещалось в рамку, просто исчезало — и при просмотре (`/render`), и при экспорте
(ascii и markdown идут через тот же `render_layout()`). Для AI-readable формата это
критично: контент макета должен быть полностью читаем, а не обрублен.

# Задача

Добавить перенос текста по словам внутри рамки псевдографики — как при просмотре,
так и при экспорте:

- текст переносится по словам в пределах ширины контентной области (ширина блока
  минус рамка);
- явные переносы строк (`\n`) сохраняются;
- слово длиннее ширины области разрезается посимвольно (hard split);
- строки, не поместившиеся по высоте, не рисуются (рамка остаётся нетронутой);
- JSON-экспорт хранит исходный контент без изменений (это данные, а не рендер).

# Исследование

1. **Одна точка изменения** — и просмотр, и экспорт идут через
   `LayoutService.render_layout()` → `PseudoGraphicRenderer.render()`:
   - просмотр: `GET /api/layouts/{id}/render` → `<pre>` с ASCII + HTML-overlay
     (overlay рисует только рамки, текст — из `<pre>`);
   - экспорт: `GET /api/layouts/{id}/export` → `ascii` и `markdown` вызывают
     `render_layout()`, `layout_json` — сырые данные блоков.
   Достаточно поправить `_draw_content()`.
2. **Клиент не рендерит текст** — `editor.js` работает только с overlay и
   inline-редактором (0012); канвас рисуется сервером через HTMX.
3. **Формат псевдографики не меняется** — меняется только наполнение ячеек внутри
   рамки; символы рамок, сетка и координаты не затрагиваются.
4. **Алгоритм** — жадный word-wrap (как `textwrap`, но с сохранением явных `\n`
   и hard-split длинных слов). Реализован вручную, без `textwrap`: стандартная
   библиотека не сохраняет пустые строки из `\n\n` и не делает hard split.

# Выполнение задачи

Изменены 2 файла + добавлен файл задачи:

**`boxframe/services/renderer.py`**:
- Новый метод `PseudoGraphicRenderer._wrap_text(text, width)` — перенос по словам:
  явные `\n` сохраняются (в т.ч. пустые строки), слово длиннее ширины режется
  посимвольно, между словами ровно один пробел.
- `_draw_content()` — вместо `line = line[:content_w]` теперь
  `lines = self._wrap_text(block.content, content_w)`; отрисовка построчная,
  с обрезкой по высоте (`content_h`) и clamp'ом по сетке — как раньше.

**`tests/test_renderer.py`** — секция «Word wrap tests», 6 тестов:
- `test_wrap_text_unit` — юнит-тест алгоритма (перенос, `\n`, hard split, пустая строка);
- `test_word_wrap_in_border` — перенос внутри рамки, рамка цела на всех строках;
- `test_word_wrap_hard_split_long_word` — слово длиннее ширины режется посимвольно;
- `test_word_wrap_preserves_explicit_newlines` — явные `\n` не ломаются;
- `test_word_wrap_clipped_by_height` — лишние по высоте строки не рисуются;
- `test_word_wrap_no_border` — блоки без рамки переносятся по своей ширине.

# Замечания

1. **JSON-экспорт намеренно без wrap** — `layout_json` хранит исходный `content`;
   перенос — свойство рендера, а не данных. Если понадобится «что увидел — то и
   экспортировано», это отдельная задача.
2. **Множественные пробелы схлопываются** — `str.split()` без аргумента; для
   псевдографики это приемлемо (визуально незначимо), но если понадобится
   сохранение отступов — нужен другой алгоритм.
3. **Перенос применяется ко всем блокам**, включая `border_style="none"` — «рамка»
   для них — их собственные границы (x, y, w, h). Поведение едино для всех типов.
