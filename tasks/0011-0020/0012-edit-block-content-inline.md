# Суть проблемы

В редакторе не было способа отредактировать текст блока: UI позволял только добавлять,
перемещать, менять размер, менять z-порядок и удалять блоки. Бэкенд при этом уже
поддерживал обновление контента — схема `BlockUpdate` в `api/layouts.py` принимает
`content`, API-тест `test_update_block` это покрывает — но единственный способ
изменить текст был прямой API-вызов. Асимметрия CRUD-возможностей в интерфейсе,
аналогичная задаче 0011 (удаление макета).

# Задача

Добавить inline-редактирование текста блока в редакторе:

- двойной клик по блоку на канвасе → textarea прямо над блоком с текущим текстом;
- `Enter` — сохранить, `Shift+Enter` — перенос строки, `Esc` — отмена;
- клик вне поля тоже сохраняет (blur);
- покрытие тестами: полный сценарий через UI (e2e) — сохранение и отмена.

# Исследование

1. **Бэкенд уже полный** — `PUT /api/layouts/{layout_id}/blocks/{block_id}` со схемой
   `BlockUpdate.content` (`api/layouts.py`), `LayoutService.update_block()`, API-тест
   `test_update_block` существует. Изменения бэкенда не потребовались.
2. **Рендерер поддерживает многострочный content** — `_draw_content()` в
   `services/renderer.py` разбивает контент по `\n` и обрезает строки по ширине
   контентной области (ширина блока минус рамка). Правильный выбор — textarea, а не
   однострочный input; формат псевдографики не меняется.
3. **Координатная система общая** — превью блоков позиционируются относительно
   `.render-wrapper` по формуле `padding_offset(16) + grid × char_size`, а wrapper
   расположен в левом верхнем углу `.canvas-container` (у контейнера нет padding).
   Overlay редактирования использует ту же формулу с измеренными `charWidth`/`charHeight`.
4. **Alpine.js 3.14.3 не поддерживает key-модификатор `.exact`** — проверено по
   исходнику CDN (`unpkg.com/alpinejs@3.14.3/dist/cdn.min.js`): ноль вхождений `exact`.
   Директива `@keydown.enter.exact.prevent` никогда не срабатывала: e2e-тест показал,
   что редактор открывается, но Enter не сохраняет. Решение — явный обработчик
   `onEditKeydown()`.
5. **dblclick предшествуют две пары mousedown/mouseup** — `onCanvasMouseDown` на
   канвасе запускает drag-режим «move», глобальный mouseup коммитит безвредный PUT с
   теми же координатами. Обработчик dblclick очищает drag-состояние
   (`_clearDragState()`).
6. **`tests/e2e/test_drag_drop.py` бит (предсуществующее)** — 7 тестов падают и на
   чистом checkout (проверено через `git stash`): ждут текст «Preview», удалённый
   при редизайне (задача 0010). К текущей задаче не относится.
7. **Конфликт event loop при смешанном прогоне e2e + API** — запуск Playwright (sync)
   и async API-файстуров в одной pytest-сессии даёт `RuntimeError` в API-тестах.
   Проверено на старых тестах (`test_projects.py` e2e + API) — предсуществующее.
   Сьюты запускаются раздельно.

# Выполнение задачи

Изменены 3 файла + добавлен файл задачи:

**`templates/pages/editor.html`**:
- CSS `.block-edit-overlay` и textarea: моноширинный шрифт с метриками `<pre>`
  (11px, line-height 1.3), чтобы текст не «прыгал» при открытии редактора.
- `@dblclick="onCanvasDblClick($event)"` на `.canvas-container` + `title`-подсказка.
- Разметка overlay: textarea с `x-model="editText"`, `@keydown="onEditKeydown($event)"`,
  `@blur="saveBlockContent()"`.

**`static/js/editor.js`**:
- Состояние: `editingBlock` (редактируемый блок), `editText` (содержимое textarea).
- Геттер `editOverlayStyle` — позиционирование над блоком: `16 + x·charWidth`,
  `16 + y·charHeight`, размер `w·charWidth × h·charHeight`.
- `onCanvasDblClick()` — находит блок под курсором (тот же hit-test, что и для
  drag), очищает drag-состояние, открывает редактор с текущим контентом, фокус и
  выделение текста.
- `onEditKeydown()` — `Enter` (без Shift) → сохранить, `Shift+Enter` → перенос,
  `Esc` → отмена.
- `_commitEdit()` — `PUT` с `{content}`, повторный рендер канваса; при ошибке сети
  редактор открывается заново, чтобы пользователь мог повторить.
- Защита в `onCanvasMouseDown()`: клик внутри overlay не запускает drag.

**`tests/e2e/test_editor.py`**:
- Хелпер `_create_project_with_block()` — проект и макет через UI, блок через API,
  перезагрузка страницы.
- `test_double_click_edits_block_content` — двойной клик → textarea со старым текстом
  → ввод → Enter → редактор закрывается, `GET /api/layouts/{id}` возвращает новый
  контент.
- `test_double_click_esc_cancels_edit` — двойной клик → ввод → Esc → редактор
  закрывается, контент не изменился.

# Замечания

1. **Alpine 3.14.3: нет модификатора `.exact`** — для «Enter без модификаторов»
   использовать явный обработчик `keydown`, а не директивные модификаторы. При
   обновлении Alpine проверить поддержку модификаторов перед упрощением.
2. **`test_drag_drop.py` требует отдельного фикса** — сьют не обновлён после редизайна
   редактора (0010): ждёт текст «Preview», которого в новом редакторе нет. Все 7
   тестов падают на этапе создания layout'а.
3. **e2e и API тесты запускать отдельными pytest-вызовами** — смешанный прогон ломает
   API-файстуры (event loop, предсуществующее).
4. **API-first подтверждён повторно** (как в 0011) — эндпоинт обновления контента
   существовал без UI; при добавлении CRUD-операций сверять наличие UI-элемента,
   а не только API.
5. **Многострочный контент** — рендерер уже обрабатывает `\n`, textarea поддерживает
   его нативно; формат псевдографики (ядро продукта) не затрагивался.
