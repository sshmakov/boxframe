# Суть проблемы

Свойства блока (стиль линии/рамки, позиция, размер, порядок, текст) можно
было менять только через крошечный select стиля в списке элементов
сайдбара — контекста у выбранного блока на канве не было: рядом с
выделенным блоком (задача 0016) была только рамка с иконками ⧉/✕ и ручкой
ресайза. Чтобы поменять, например, стиль линии, нужно было искать блок в
списке, а остальные свойства (x/y/w/h/order/content) на канве менять
только drag'ом — без точных числовых значений.

# Задача

Добавить плавающую панель свойств блока, которая появляется рядом с
выделенным блоком на канве и позволяет менять его свойства: стиль линии
(solid/dashed/dotted/double/none), позицию (X/Y), размер (W/H), порядок
(Order) и текст (Content). Изменения должны сразу сохраняться на сервере.

# Исследование

1. **Канва рендерится на сервере, оверлеи — на клиенте** — превью блоков
   генерирует `PseudoGraphicRenderer.render_html_preview()`, а рамка
   выделения (0016) — клиентский оверлей в `.canvas-container`
   (position: absolute в координатах контента). Панель свойств реализована
   тем же паттерном: отдельный клиентский оверлей, координаты считаются из
   сеточных координат блока × измеренный размер символа. Панель
   скроллится вместе с канвой и следует за блоком при move/resize
   (getter пересчитывается при изменении x/y/w/h).
2. **Бэкенд менять не пришлось** — `PUT /api/layouts/{id}/blocks/{bid}`
   принимает частичное обновление (`BlockUpdate` + `exclude_none`): любой
   подмножество полей `{border_style, x, y, width, height, order, content}`
   уходит одним запросом. Список стилей уже отдаётся
   `/api/projects/{id}/info` (`border_styles`) и лежит в
   `this.borderStyles`.
3. **mousedown на канве начинает pending-drag** — клик внутри панели без
   защиты привёл бы к тому, что mouseup снимет выделение (логика
   «клик по пустому месту»), и панель бы закрылась. Добавлены guards
   `e.target.closest('.block-props')` в `onCanvasMouseDown` и
   `onCanvasDblClick` — по образцу существующих guards для
   `.block-selection` и `.block-edit-overlay`.
4. **Позиционирование** — панель 208px шириной: влезает справа от блока →
   справа; иначе влево (если `bx - panelW - 12 >= 8`); иначе под блок.
   Вертикально — от верхнего края блока, с клампингом в видимую область
   канвы (`clientHeight + scrollTop`). «Влезает ли» считается в
   координатах контента (`clientWidth + scrollLeft`), т.к. панель живёт в
   координатах контента, а не вьюпорта.
5. **Линии — особый случай** — `hline` всегда высотой 1, `vline` шириной 1
   (так же, как в drag-ресайзе); клампинг W/H учитывает это, иначе в
   панели можно было бы «сломать» линию, введя высоту 2.

# Выполнение задачи

Изменено 3 файла:

**`boxframe/templates/pages/editor.html`**:
- CSS `.block-props` — тёмная карточка (фон `var(--bg-card)`, тень как у
  dropdown), `z-index: 200` (выше рамки выделения — 100).
- Разметка панели внутри `.canvas-container`, `x-show="selectedBlock &&
  !editingBlock"` (как у рамки — не мешает инлайн-редактору):
  - заголовок: тип блока + кнопка «×» (снять выделение);
  - сетка 2 колонки: Style (select, во всю ширину), X/Y, W/H, Order,
    Content (input, во всю ширину).
- Поля привязаны через `:value` + `@change` — значение уходит на сервер
  по Enter/blur, после успешного PUT `:value` перерисовывает поле
  (в т.ч. клампнутое значение).

**`boxframe/static/js/editor.js`**:
- `propsPanelStyle` (getter) — позиция/ширина панели (п. 4
  «Исследование»).
- `updateSelectedBlock(props)` — общий PUT с сохранением старых значений и
  откатом `Object.assign(b, old)` при ошибке; после успеха —
  `refreshRender()`.
- `updateSelectedXY` / `updateSelectedWH` / `updateSelectedOrder` /
  `updateSelectedContent` — парсинг + клампинг (границы layout, минимум
  1×1, линии 1-клеточные, order ≥ 0); NaN → поле сбрасывается в текущее
  значение, запрос не уходит.
- Guards `.block-props` в `onCanvasMouseDown` и `onCanvasDblClick`.

**`tests/e2e/test_editor.py`** (+2 теста):
- `test_properties_panel_shows_next_to_selected_block` — клик по блоку →
  панель видна, заголовок = тип блока, select показывает текущий стиль.
- `test_properties_panel_updates_border_style` — select → `dashed`,
  значение сохраняется в БД (polling API, как в соседних тестах).

# Замечания

1. **Высота панели для клампинга — константа 300px** в `propsPanelStyle`.
   Если в панель добавят поля и она станет выше/ниже, константу нужно
   обновить (иначе клампинг по верхнему краю будет неточным).
2. **Дублирование функциональности** — select стиля в списке элементов
   сайдбара (`updateBlockStyle`) теперь дублирует поле Style в панели.
   Оставлен намеренно (быстрый доступ без выделения), но при желании его
   можно убрать из списка.
3. **Панель не переживает перезагрузку** — как и само выделение (0016,
   замечание 2): состояние только в памяти Alpine.
4. **Клампинг W/H в панели мягче, чем в drag-ресайзе** — drag требует
   минимум 2×2 для нелиний, панель позволяет 1×1 (API не ограничивает).
   Если это нежелательно, в `updateSelectedWH` стоит поднять минимум до 2
   для нелиний.
5. **Конфликт e2e + API в одном pytest-процессе** (pre-existing): запуск
   `pytest tests/e2e/ tests/api/` вместе даёт `RuntimeError: This event
   loop is already running` у API-тестов — playwright sync API конфликтует
   с pytest-asyncio. Тесты нужно запускать раздельными командами.
