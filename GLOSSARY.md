# Глоссарий терминов boxframe

Термины, принятые в проекте: доменные (продукт), модель данных, рендеринг,
редактор, режимы/хранилища, импорт/экспорт, тестирование, задачи.

## Продукт

- **boxframe** — редактор UI-макетов в псевдографике. Макеты машиночитаемы,
  самодокументируемы и оптимизированы для потребления ИИ-агентами.
- **Псевдографика** — представление UI-макета ASCII/Unicode box-drawing
  символами (─│┌┐└┘ и т.п.) на моноширинной сетке. Ядро продукта: формат не
  меняется.
- **Клетка** — одна ячейка моноширинной сетки (один символ). Единица
  координат, размеров и смещений во всём проекте.
- **Проект** (`Project`) — именованная группа макетов; верхний уровень
  иерархии в БД.
- **Макет** (`Layout`) — холст 2D-сетки с необязательными размерами
  width×height и набором блоков.
- **Блок** (`Block`) — базовый элемент макета: позиция (x, y), размер
  (width, height), тип, содержимое, стиль границы, z-порядок, meta.
- **Дерево блоков** — вложенность блоков через `parent_id` /
  `children`; хранится в SQLite. Координаты детей — относительные к
  родителю (в БД и в JS-списках).
- **Контейнер** — блок, способный содержать детей: `box` и `grid`
  (`_findDropContainer()` в `editor.js` принимает только их).
- **Атомарный блок** — блок без детей: `hline`, `vline`, `button`,
  `divider` (в hit-test исключается из спуска в детей).
- **Палитра** — панель типов блоков в сайдбаре редактора; источник
  drag-and-drop и клика для создания блоков.
- **Холст** (canvas) — всё доступное пространство редактора: блоки можно
  размещать где угодно, включая область за границами макета; канвас
  автоматически расширяется под блоки.
- **Размеры макета** — необязательные width/height layout: рисуются как
  визуальная линия границ на холсте, не ограничивают размещение блоков и
  не являются частью ASCII-арта.
- **z-порядок** (`order`) — порядок отрисовки блоков: больший `order`
  рисуется поверх.

## Типы блоков

`BLOCK_TYPES` в `models/block.py` (дублируется в `static/js/core/renderer.js`):

| Тип        | Назначение                                |
|------------|-------------------------------------------|
| `box`      | Универсальный контейнер                   |
| `header`   | Заголовок страницы                        |
| `footer`   | Подвал страницы                           |
| `sidebar`  | Боковая колонка                           |
| `content`  | Основная область контента                 |
| `button`   | Кнопка (особая форма по высоте, autosize) |
| `input`    | Поле ввода                                |
| `textarea` | Многострочное поле                        |
| `image`    | Заглушка изображения                      |
| `divider`  | Мультилинейный разделитель с подписью     |
| `hline`    | Горизонтальная линия (1 строка)           |
| `vline`    | Вертикальная линия (1 колонка)            |
| `text`     | Простой текст (autosize по содержимому)   |
| `grid`     | Сетка-контейнер с перегородками           |

## Стили границ

`BORDER_STYLES` — применяются и к рамкам блоков, и к линиям
(`hline`/`vline` рисуются символом выбранного стиля):

- **solid** (─│), **dashed** (┄┆), **dotted** (┈┊), **double** (═║),
  **none** (без рамки).
- **Borderless-контейнер** — контейнер с `border_style=none`: сохраняет
  тот же 1-cell padding и inner-клип, что и с рамкой; дети рендерятся
  независимо от рамки (задача 0070 — hit-test, 937a50e — рендер детей).

## Поля блока

- **content** — текстовое содержимое блока (до 2000 символов).
- **meta** — JSON-словарь дополнительных свойств: `fill`, `text_align`,
  `vertical_align`, `arrow_start`/`arrow_end` (hline/vline),
  `cols`/`rows`/`col_widths`/`row_heights` (grid).
- **Placeholder (lorem)** — псевдо-текст, который рендерер генерирует для
  пустого блока типа `content`.
- **Fill** — символ заливки внутренней области (`meta.fill`, ровно одна
  клетка), применяется только к типам из `FILL_TYPES`.
- **Arrows** — стрелки на концах линий hline/vline (`meta.arrow_start` /
  `meta.arrow_end`): 6 форм головок (arrow, arrow-open, diamond,
  diamond-open, circle, circle-open) или `none`.
- **Выравнивание** — выравнивание текста внутри блока по горизонтали (`meta.text_align` - left/center/right) и
  по вертикали (`meta.vertical_align` - top/middle/bottom).

## Рендеринг

- **Рендерер** (`PseudoGraphicRenderer`, `services/renderer.py`) —
  преобразует дерево блоков в ASCII-арт на 2D-сетке.
- **RenderBlock** — плоское представление блока для рендера.
- **render()** — отрисовка дерева на сетке с обработкой вложенности.
- **render_simple()** — convenience-метод: рендер из raw-словарей.
- **ASCII-слой** — текстовый вывод (сетка символов).
- **HTML-оверлей** (HTML preview) — позиционированные div'ы поверх
  ASCII-слоя (рамки, подписи, линии); используется в редакторе.
- **Block preview** (`.block-preview`) — div-обёртка блока в
  HTML-оверлее: позиционирование, z-index по `order`, `overflow:hidden`
  у контейнеров (клип детей). Генерится `_block_preview_html()` /
  `renderBlock()`.
- **Outline** (`.block-border`) — видимая рамка блока в
  HTML-оверлее, рисуется у **каждого** блока (не только выделенного).
- **Block line** (`.block-line`) — рамка-линия для `hline`/`vline`
  (`.block-line--h/--v`) и сегменты `divider` (`.block-line--seg`).
- **Parity** — побайтовое совпадение вывода Python- и JS-рендереров;
  держится parity-тестами (`tests/test_js_renderer_parity.py`).
- **JS-порт рендерера** (`static/js/core/renderer.js`) — клиентский
  рендерер для static-режима; формат вывода идентичен Python.
- **Inner area / padding** — внутренняя область контейнера: дети
  размещаются с 1-cell padding от рамки родителя и клипятся по
  inner-области.
- **Клип** (clip) — обрезка контента/детей по границам области.
- **Word-wrap** — перенос слов содержимого по внутренней ширине блока
  при рендере: применяется ко всем блокам с контентом.
- **Autosize** — автоматический пересчёт размера блока по содержимому; 
  пересчитывается при создании и при обновлении `content`/`border_style`/`block_type`; 
  ручной resize сохраняется; `replace_blocks` (undo/redo) размер не пересчитывает.
- **Junctions / frame-узлы** — угловые и перекрёстные символы рамки
  (┌┬┐├┼┤└┴┘); у grid рисуются по реально отрисованным сегментам.

## Grid (сетка-контейнер)

- **Перегородки** — внутренние линии grid: число колонок/рядов —
  `meta.cols`/`meta.rows` (дефолт 3/2); рисуются только у grid со
  структурой.
- **Структура grid** — наличие валидного `meta.cols` **или**
  `meta.rows` (`grid_has_structure()` / `gridHasStructure()`).
- **Legacy grid** — grid без структуры (макеты до задачи 0061, когда
  `grid` был plain box): рендерится как обычный box (рамка + hint
  `[grid]` + дети, без перегородок); панель свойств показывает 1/1
  (эффективную структуру), первое изменение cols/rows материализует
  структуру.
- **Кастомные ширины/высоты** — `meta.col_widths`/`meta.row_heights`:
  массивы целых на колонку/строку; некорректный массив → равномерный
  split; последняя колонка/строка впитывает дельту (`grid_split()` /
  `gridSplit()`).
- **Span** — span-область ребёнка grid: объединение целых ячеек, которые
  его прямоугольник задевает; внутри области перегородки гасятся только
  там, где их реально пересекает ребёнок (задачи 0062–0068).
- **Ручки внутренних границ** — редакторские маркеры на перегородках
  grid при одиночном выделении (`.grid-handle--v`/`--h`); drag сдвигает
  перегородку, commit пишет `meta.col_widths`/`row_heights`.

## Редактор

- **Выбор** — выделение блоков: одиночный (клик), множественный
  (Shift+клик), marquee.
- **Marquee (rubber-band)** — выделение рамкой перетаскиванием мыши
  (`.marquee`).
- **Selection frame** (`.block-selection` / `.block-selection__frame`)
  — рамка выделения вокруг одиночно выделенного блока (при
  множественном — bounding box группы); на ней же resize-ручки
  `.sel-resize` и ручки grid-перегородок; показывается при
  `selectedBlock && !editingBlock`. Не путать с block border (рамка
  самого блока) и marquee.
- **Hit-test** — определение блока под курсором; учитывает z-порядок и
  вложенность (спуск в детей контейнера).
- **Drop container / drop target** — контейнер, в который можно
  перетащить блок; подсвечивается во время drag
  (`.block-preview--drop-target`).
- **Reparent** — смена родителя блока при переносе в контейнер
  (координаты пересчитываются в относительные).
- **Resize-ручки** — угловые маркеры для изменения размера блока.
- **Панель свойств** — плавающая панель выделенного блока (позиция,
  размер, стиль, z-порядок, содержимое, meta; секции по типу блока).
- **Undo/Redo** — история изменений: хоткеи Ctrl+Z / Ctrl+Shift+Z /
  Ctrl+Y; `core/history.js` (`withHistory`).
- **Snapshot** — снимок полного состояния макета (блоки + layout);
  undo/redo — snapshot-стеки без лимита.
- **Coalescing** — склейка consecutive-обновлений одного блока в окне
  500 мс в одну запись истории.
- **Буфер undo** — переживает перезагрузку страницы (persist в
  localStorage в static-режиме).
- **Clipboard (копирование выбора)** — копирование выделенных блоков в
  буфер обмена как ASCII-фрагмент (`selectionToAscii()`).

## Режимы и хранилища

- **Web-режим** — редактор с бэкендом: страница `/editor/...`, данные
  через API (FetchStore).
- **Static-режим** — редактор без бэкенда:
  `static/editor/index.html` открывается напрямую (работает через
  `file://`), макет в localStorage.
- **Store** — единый интерфейс хранилища (`core/store.js`):
  `FetchStore` (API, web-режим), `LocalStorageStore` (static-режим,
  key `boxframe.static.layout`), `MemoryStore` (in-memory, fallback).
  `editor.js` не знает о fetch.
- **replaceState** — полная замена состояния макета в сторе (local —
  напрямую, web — batch `PUT /blocks`); путь undo/redo и импорта.
- **NoCacheStaticFiles** — подкласс StaticFiles с
  `Cache-Control: no-cache`: браузер ревалидирует статику при каждом
  запросе (задача 0069, доводка).

## Импорт / экспорт

- **Экспорт** — выгрузка макета в JSON / Markdown / ASCII
  (`GET /api/layouts/{id}/export`); JSON несёт `order` для round-trip
  z-порядка.
- **Импорт** — загрузка JSON-макета: `core/import.js`
  (`parseLayoutJson` — вложенный экспорт → плоский список
  `block_type`/`meta`/`parent_id`; `prepareImport` — подготовка к
  применению).
- **Режимы импорта** — `add` (добавить блоки поверх существующих: новые
  id, order выше текущего максимума) и `replace` (заменить всё
  содержимое); при непустом редакторе — `confirm`.
- **Legacy JSON** — экспорт старых версий (без структуры grid и т.п.);
  импортируется без инжекта структуры (задача 0069).

## API и сервисы

- **LayoutService** (`services/layout_service.py`) — бизнес-логика:
  CRUD layout/blocks, render, export.
- **Batch replace** — `PUT /api/layouts/{id}/blocks`: полная замена
  набора блоков (undo/redo); id из payload сохраняются.
- **Render endpoint** — `GET /api/layouts/{id}/render`: ASCII + HTML
  preview (параметры `char_width_px`, `char_height_px`).

## Тестирование

- **Parity-тесты** — сравнение вывода Python- и JS-рендереров
  (`tests/test_js_renderer_parity.py`).
- **API-тесты** — unit-тесты роутов (httpx + TestClient, `tests/api/`).
- **JS-тесты** — тесты клиентского кода (node:test, `tests/js/`).
- **E2E-тесты** — Playwright-сценарии (`tests/e2e/`); требуют запущенного
  сервера на :8000; запускать отдельной командой (playwright sync API
  конфликтует с pytest-asyncio в одном процессе).

## Задачи и релизы

- **Задача** — markdown-файл в `tasks/NNNN-.../NNNN-name.md` по шаблону
  `0000-template.md`; нумерация сквозная, подпапки по десяткам.
- **Backlog** — `tasks/backlog/todo-NNNN-name.md`: идеи без номера
  задачи; при конкретизации получают номер и переезжают в подпапку.
- **Bump** — релиз: `scripts/bump.sh` (команда `/bump`) — bump минора в
  `pyproject.toml`, commit, тег `vX.Y.Z`, push.
- **GitHub Pages** — публикация static-редактора по пушу в `develop`:
  <https://sshmakov.github.io/boxframe/editor/>.
